## Находки

Блокирующих нет.

### 1. TOCTOU-гонка в `files.Save`: конкурентная запись одного пути молча перезаписывает файл — замечание

- **Где:** `internal/files/files.go:58` (проверка `os.Stat`) и `:90` (`os.Rename`)
- **Чем грозит:** два конкурентных `Save` одного `{app}/{version}/{filename}` оба проходят Stat-проверку, второй `Rename` затирает первый. Последовательный повтор (критерий плана) отклоняется корректно — покрыто тестом. На уровне сервиса от дублей защищает UNIQUE в БД, но `files` сам по себе гарантию «перезапись запрещена» под гонкой не держит.
- **Предлагается:** ничего не менять сейчас; если захочется строгой гарантии — `os.Link`+`os.Remove` вместо `Rename` (link не перезаписывает) или `O_CREATE|O_EXCL`-маркер.

### 2. Prerelease старшего мажора становится latest — замечание (поведение зафиксировано тестом как контрактное)

- **Где:** `internal/store/store.go:352` (`LatestVersion`)
- **Чем грозит:** после заливки `2.0.0-beta` при существующем релизе `1.10.0` ссылка `latest` начнёт отдавать бету. Это корректный semver (prerelease понижает только относительно релиза той же версии) и не противоречит плану, но человека может удивить.
- **Предлагается:** осознать и оставить, либо решением человека исключать prerelease из авто-latest при наличии релизов.

### 3. `wrapExists` детектит дубль по подстроке текста ошибки — замечание

- **Где:** `internal/store/store.go:93`
- **Чем грозит:** завязка на строку `"UNIQUE constraint failed"` конкретного драйвера; смена драйвера/формата сообщения молча превратит `ErrExists` в generic-ошибку. С текущим ncruces-драйвером работает (покрыто тестами, включая гонку).
- **Предлагается:** при следующем касании — `errors.As` на тип ошибки драйвера с проверкой кода `SQLITE_CONSTRAINT_UNIQUE`.

### 4. `parseTime` глотает ошибку парсинга — замечание

- **Где:** `internal/store/store.go:99-102`
- **Чем грозит:** повреждённый `created_at`/`expires_at` превращается в нулевое `time.Time` без сигнала; для `GetSession` нулевое время трактуется как «просрочена» (безопасная сторона), для `CreatedAt` — косметика.
- **Предлагается:** оставить; максимум — лог.

### 5. `CreateVersion` не валидирует формат sha256 — замечание

- **Где:** `internal/store/store.go:271-282`
- **Чем грозит:** слой хранения примет строку любого содержимого/длины (лишь приведёт к нижнему регистру). В реальном потоке хеш всегда считает `files.Save`, так что практического пути к мусору нет.
- **Предлагается:** оставить; опционально — проверка `^[0-9a-f]{64}$` в сторе.

## Допущения

- База для diff-покрытия — ветка `develop` (состояние до волны 2): изменённые строки = весь код T2/T3, что и есть скоуп R2-test.
- «Большой файл» = 128 MiB: заведомо больше любых внутренних буферов (io.Copy — 32 KiB), при этом тест укладывается в секунды; потоковость проверена ассертом на `runtime.MemStats.TotalAlloc` (< размера файла/4), под `-short` тест пропускается.
- Поведение «prerelease старшего мажора выигрывает latest» (находка 2) зафиксировано тестом как контрактное — оно следует из semver и формулировки плана «максимум по semver»; если человек решит иначе, тест `prerelease_of_higher_major_wins_over_lower_release` нужно будет поменять вместе с кодом.
- Гонка `CreateVersion` проверяется 8 горутинами через один пул соединений одного процесса (реальный сценарий сервиса); межпроцессная гонка не моделировалась.
- Тесты store написаны в пакете `store` (не `store_test`) — так уже сделано в существующем `store_test.go`, и нужен доступ к `openTemp`.
