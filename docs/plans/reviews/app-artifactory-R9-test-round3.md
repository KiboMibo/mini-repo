# R9-test, круг 3 — покрытие инверсии `:has()` (F25)

Дата: 2026-08-09. База: `7b8d004`. Отчёты кругов 1 и 2 не изменялись.

**Статус: PASS.** 12 пакетов зелёные, находок нет. Дописано два ассерта в
существующий `TestBackArrowOffsetsAgree`, новых тестовых функций не заводил.

## Что покрыл

Сначала прогнал четыре мутации против **существующего** теста — чтобы не писать
то, что уже стережётся. Оказалось, две из четырёх уже краснели:

| Мутация | До правки | После |
|---|---|---|
| M1 переворот на `main:has(.page-head){padding-left:2.6rem}` | КРАСНЫЙ (на форме записи) | КРАСНЫЙ |
| M2 правило-исключение удалено (состояние до F25) | **ЗЕЛЁНЫЙ** | КРАСНЫЙ |
| M3 `padding-left` исключения разошёлся с `main{padding-right}` | **ЗЕЛЁНЫЙ** | КРАСНЫЙ |
| M4 базовое правило сужено до `1rem` | КРАСНЫЙ | КРАСНЫЙ |

Поэтому дописал ровно два ассерта, закрывающих M2 и M3, плюс один прямой на
инверсию:

```go
// правило, а не упоминание: в layout.html эта запись разобрана комментарием
if regexp.MustCompile(`(?m)^main:has\(`).MatchString(css) { … }
if narrow := remProp(t, css, "main:not(:has(.page-head))", "padding-left"); narrow != right { … }
```

Первый — прямой сторож инверсии с объяснением причины в тексте ошибки. Он нужен
потому, что M1 существующий тест ловил **по форме записи** (`main{padding} = "0
1rem": ожидалось 0 <right> 0 <left>`), а не по существу: переворот, записанный в
четырёхзначной форме, проехал бы мимо этого сообщения. Проверил отдельной
мутацией **M1b** (`main{padding:0 1rem 0 1rem}` + `main:has(.page-head){padding-left:2.6rem}`)
— теперь краснеет тремя ассертами сразу, включая тот, что называет причину.

Второй закрывает M2 и M3 одним равенством `исключение.padding-left ==
main.padding-right`: поля страниц без стрелки симметричны. Отсутствие правила —
`Fatalf` от `declOf`, то есть M2 тоже красный.

## Реакция на мутации после правки

| Мутация | Реакция | Сообщение |
|---|---|---|
| B0 нетронутый F25 | ЗЕЛЁНЫЙ | — |
| M1 переворот, `padding:0 1rem` | КРАСНЫЙ | форма `main{padding}` |
| M1b переворот в четырёхзначной форме | КРАСНЫЙ | ×3, включая «широкое поле навешено через `main:has(...)`» |
| M2 исключение удалено | КРАСНЫЙ | «нет правила `main:not(:has(.page-head))`» |
| M3 `padding-left` исключения = 3rem | КРАСНЫЙ | «поля разъедутся: 3rem != 1rem» |
| M4 базовое сужено до 1rem | КРАСНЫЙ | «стрелка обрежется краем страницы» |
| M5 оба поля 1.5rem согласованно | ЗЕЛЁНЫЙ | проверка в обратную сторону |

M5 — контроль на переспецификацию: тест не диктует значений, только связи.

По вопросу командира «должна ли краснеть M2»: **да.** Удаление исключения не
ломает функциональность, но возвращает регрессию Н2 (прокрутка на корневом
списке в полосе ~353–370px), которую F25 и снимал. Регрессия, снятая правкой и
не закреплённая тестом, возвращается при следующей уборке CSS — а стоимость
сторожа здесь одна строка.

Первая редакция ассерта была `strings.Contains(css, "main:has(")` и падала на

той же конвенции, что и `declOf`.

## Что покрывать отказался

**Ничего из списка командира.** Все четыре пункта — связи между числами или
между правилами, не пересказ CSS: пара «базовое/исключение» несёт совместимость
с браузерами без `:has()`, равенство с `padding-right` несёт симметрию полей.
Пересказом было бы `padding-left:1rem` само по себе — этого в тесте нет,
проверяется равенство с другим числом.

**Замер «минимальная ширина `/` упала ровно на 25.6px» не проверял.** Это
измерение в браузере: нужен живой сервер, посев данных и раскладка движка. В моих
средствах (Go, чтение шаблона) такого нет, а поднимать браузерный стенд ради
одного числа — не мой инструмент и дублирование R9-qa. **Подтверждение снимает
R9-qa.** Косвенно замер согласуется с CSS: 2.6rem − 1rem = 1.6rem = 25.6px при
корневом шрифте 16px, и тест теперь стережёт обе части этой разности.
