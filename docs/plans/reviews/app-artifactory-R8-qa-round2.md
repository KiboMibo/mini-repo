## Что проверено на живом сервисе

Сборка `go build -o /tmp/apprepo-qa2 ./cmd/apprepo`; сервис поднят как
`apprepo serve -data-dir /tmp/qa9/data -addr 127.0.0.1:18290 -max-upload 209715200`
(`/opt/apps` не тронут). Фикстуры — настоящие кросс-сборки `cmd/compile`
(размеры совпали с замерами F22 байт в байт), universal собран склейкой двух
darwin-срезов, архив 14,6 MB, `.jar`, а также вручную собранные враждебные и
краевые образцы.

### Автоопределение крупных сборок (то, что чинилось)

Все пять заливок — `PUT` **без** `?platform=`, коды в таблице выше. Через форму
UI с «detect automatically» — то же самое: `303` и в БД `darwin/arm64` для
27-мегабайтного Mach-O, `windows/amd64` для 29-мегабайтного PE.

### Расхождение метки и содержимого на крупных файлах

Круг назад определить было нечего, и чужая метка проезжала молча. Теперь:

| Сценарий | Факт |
|---|---|
| Mach-O 27 MB, `?platform=windows/amd64` | **409 `platform_mismatch`**, «the uploaded file is built for darwin/arm64…» |
| PE 29 MB, `?platform=any` | **409** |
| universal 55,6 MB, `?platform=darwin/arm64` | **409** |
| UI: Mach-O 27 MB, в форме `windows`+`amd64` | **409**, тот же текст на странице |

После каждого отказа: версии нет в БД, каталога версии нет на диске,
`{data-dir}/.tmp` пуст.

### Что по-прежнему не определяется

| Файл | Факт |
|---|---|
| архив `.tar.gz` 14,6 MB без `?platform=` | **400 `platform_required`** |
| `.jar` (zip) без `?platform=` | **400 `platform_required`** |
| fat-заголовок с `nfat_arch = 0x7fffffff` | **400** (`""` — потолок `maxFatArch`) |
| **голый COFF `.obj` без `MZ`** | **400** — изменение поведения, `debug/pe` такое принимал |
| **Java `.class`** (`0xcafebabe`, как у fat Mach-O) | **400** — проверка «каждый срез обязан быть Mach-O» ловит |

### Изменение поведения: бомбы опознаются

| Файл | Факт |
|---|---|
| ELF, `e_shoff` в космос, `e_shnum = e_shstrndx = 0xffff` | **201, `linux/amd64`** |
| PE, `NumberOfSymbols = 0xffffffff` | **201, `windows/amd64`** |

Изменение считаю правильным и не находкой: в этих файлах врёт не заголовок, а
таблицы, на которые он указывает, а таблицы больше не читаются. Заголовок честно
называет машину, и метка «под что собрано» получается верная. Важно другое —
это перестало быть проверкой целостности файла (ею оно и не было, но раньше
кривой артефакт отваливался как побочный эффект). Формулировка добавлена в
`docs/api.md` и в инвариант `CLAUDE.md` явным абзацем: целостность проверяет
`sha256`, а не определение платформы.

В журнале сервиса за весь прогон — ни одной паники и ни одной строки
`detect platform: …`.

## Находки

### 1. Замечание — синхронность README и `deploy/apprepo.service` ничем не проверяется

**Где:** `README.md`, раздел «Деплой (systemd)» — код-блок с юнитом против
`deploy/apprepo.service`; инвариант в `CLAUDE.md` («код-блок юнита в README —
копия `deploy/apprepo.service` и обязан меняться вместе с ним»).

**Что не так.** Инвариант есть, а проверки нет. Наглядно: правя комментарий в
двух местах в рамках этой самой задачи, я сформулировал его в README и в юните
чуть по-разному, и разъехались они мгновенно. Поймала это не внимательность, а
разовый скрипт, который я написал для сверки; в норме такого скрипта никто не
запускает. До этой задачи блоки были идентичны (проверено на `6ac9e66` и
`b47717f`) — то есть инвариант держался на аккуратности, и первый же случай
одновременной правки его сломал.

**Чем грозит.** Расхождение копии юнита не ломает сборку и не ловится тестами, а
читают при развёртывании как раз README. Сегодня разошёлся комментарий, завтра
разойдётся `ReadWritePaths=` — а это уже падение старта с `status=226/NAMESPACE`,
про которое в том же README написано отдельным разделом.

**Что предлагается.** Тест на десяток строк по образцу
`TestTemplatesHaveNoPlatformLiterals`: вырезать из `README.md` код-блок с
юнитом (он размечен как `ini`), сравнить с содержимым `deploy/apprepo.service`,
падать с diff'ом. Один раз написать — и инвариант перестанет зависеть от
аккуратности. Расхождение, возникшее в этой задаче, я устранил: блок пересобран
из файла юнита и совпадает с ним байт в байт.
