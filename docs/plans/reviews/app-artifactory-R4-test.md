## Находки

### 1. `Content-Disposition` отдаёт filename без кавычек — замечание

- **Где:** `internal/api/api.go:456-457`
- **Что:** `mime.FormatMediaType` для token-совместимых имён выдаёт
  `attachment; filename=myapp-linux`, а контракт в плане записан буквально как
  `filename="{filename}"`. Это валидный HTTP (RFC 6266), curl и браузеры
  обрабатывают корректно; не-ASCII имена корректно уходят в `filename*=`
  (RFC 5987). Поведенческого дефекта нет — расхождение только с буквой плана.
- **Предлагается:** ничего не менять; при желании зафиксировать формулировку в
  `docs/api.md` (задача R4-qa).
- **Тест:** `api_test.go › TestAPIHappyPath/download_latest_serves_bytes_and_headers`
  (парсит заголовок через `mime.ParseMediaType`, а не сравнением строки).

### 2. Ветки 500-ошибок хендлеров не проверяемы снаружи — замечание

- **Где:** `internal/web/web.go`, `internal/api/api.go` (список строк выше)
- **Чем грозит:** ошибки БД внутри хендлеров дают ~15% непокрытых строк этих
  файлов; при рефакторинге этих веток регрессию тесты не поймают.
- **Предлагается:** если когда-нибудь понадобится — вынести store за интерфейс
  на стороне потребителя; сейчас не стоит того (решение команды, не моё).

## Допущения

1. **База ветки.** На момент старта T7 не был влит в `test/R4-tests`; я вмержил
   `feat/T7-integration` вручную, после чего командир сбросил ветку на
   `wave/app-artifactory-w3` (коммит `2785500`, T7 в базе штатно) — работа
   продолжена на ней, ручной мерж отброшен вместе со сбросом.
2. **Prerelease-latest** — контракт, зафиксированный R2-test («prerelease
   старшего мажора становится latest»), принят как данность; проверялась только
   консистентность UI/API/download, багом не считается.
3. **Граница max-upload** проверена точно на API PUT (тело = сырые байты).
   Для UI точная граница не воспроизводима — лимит действует на всё multipart-
   тело вместе с рамками формы; для UI проверено превышение (413).
4. **Риск «память не растёт с размером файла»** из плана явным измерением RSS
   не проверялся: потоковость пути upload → temp → rename покрыта R2-test на
   уровне `files.Save`, а хендлеры читают тело только через
   `MultipartReader`/`MaxBytesReader` без буферизации (проверено чтением кода).
   Явный бенчмарк памяти при желании — отдельная задача.
5. **Покрытие `cmd/apprepo/main.go`** засчитано через отдельные прогоны
   инструментированного бинарника (`go build -cover` + `GOCOVERDIR`), слитые с
   профилем `go test`; те же сценарии CLI продублированы как обычные тесты
   (`TestUserAddCLI`), чтобы защита не зависела от способа замера.
6. `TestUserAddCLI` собирает бинарник и пропускается под `-short`.
