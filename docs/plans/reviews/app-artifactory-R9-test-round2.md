## 2. `TestBackArrowOffsetsAgree` — был зелёным по совпадению, переписан

**Ответ: совпадение, и вредное.** Старая редакция проверяла формулу прежнего
механизма:

```
.page-head{margin-left} == -(.back{width} + .page-head{gap})
main{padding-left}      == main{padding-right} + (width + gap)
```

После F24 эта арифметика ещё выполняется численно (1.6 = .8 + .8), но описывает
не то, что происходит:

* **`gap` больше не участвует.** Стрелка выведена из потока
  (`position:absolute`), и `gap` отделяет `h1` от соседей по флексу — «Latest:
  …», формы выбора latest, — а не от стрелки. Мутация **O10** (`gap` .8 → 1.4rem)
  оставляет позицию заголовка на месте, и новая редакция теста это подтверждает:
  ЗЕЛЁНЫЙ, как и должно быть. Старая на той же мутации потребовала бы менять
  `margin-left` — то есть толкала бы к настоящей поломке.
* **Load-bearing число теперь `padding-left`, и старый тест его не смотрел.**
  Мутация **O1** — удаление `.page-head{padding-left:1.6rem}`, ровно тот дефект
  В2, который F24 и чинил (заголовок уезжает на 1.6rem левее таблицы) —
  оставляла старую редакцию **ЗЕЛЁНОЙ**. Проверено на живой F24-версии файла до
  переписывания.

Новая редакция проверяет механизм, который есть на самом деле:

```
.page-head{position:relative}  .back{position:absolute;left:0;top:0}
.page-head{padding-left} == -.page-head{margin-left}   ← заголовок на край таблицы
.back{width}             <= .page-head{padding-left}   ← стрелка влезает в поле
main{padding-left}       >= main{padding-right} + вылет ← стрелка не обрезана
th:first-child,td:first-child{padding-left} == 0
.page-head h1{overflow-wrap} == anywhere
```

| Мутация | Реакция |
|---|---|
| O1 удалён `.page-head{padding-left}` | КРАСНЫЙ (старая редакция: ЗЕЛЁНЫЙ) |
| O2 `padding-left` 1.6 → 1rem, рассогласован с `margin-left` | КРАСНЫЙ |
| O3 снят `.page-head{position:relative}` | КРАСНЫЙ |
| O4 стрелка возвращена в поток | КРАСНЫЙ |
| O5 `.back{width}` 2rem — шире отведённого поля | КРАСНЫЙ |
| O6 `main{padding-left}` 2.6 → 1rem | КРАСНЫЙ |
| O7 `overflow-wrap` → `normal` | КРАСНЫЙ |
| O8 первой колонке вернули отступ | КРАСНЫЙ |
| O9bis сдвиг, padding и `main{padding-left}` изменены **согласованно** | ЗЕЛЁНЫЙ |
| O10 изменён `gap` | ЗЕЛЁНЫЙ |

O9/O10 — проверка в обратную сторону: тест не диктует конкретных чисел и не
падает на правках, поведение не меняющих.

## 3. Новые свойства: что покрыл и почему

Командир оставил решение за мной. Покрыл три из трёх, но не как пересказ CSS —
у каждого есть либо арифметическая связь с другим числом, либо внешний норматив.

**`line-height:2.4rem` у `.back` против `line-height:1.2` у `h1`** — покрыл.
Это ровно тот же класс дефекта, что и горизонтальный: связь заявлена
комментарием (`1.2 × 2rem`), держится на двух числах в разных правилах, и
разъезд молчаливый. Мутации: **V1** (`line-height:1` у стрелки) и **V2**
(изменён `line-height` у `h1`, стрелка не поправлена) — красные; **V6** (оба
изменены согласованно) — зелёный. Заодно **V7**: удаление `.back{top:0}` —
красный.

Оговорка, вынесенная в код: `font-size` у `h1` в CSS страницы **не задан**, 2rem
берётся из умолчания браузера. Тест держит это константой `h1FontSizeRem` и
падает с явным указанием поправить её, если `.page-head h1` когда-нибудь
обзаведётся своим `font-size` — иначе проверка тихо считала бы от неверного
числа.

**`overflow-wrap:anywhere`** — покрыл, одной строкой. Свойство закрыло
измеренный дефект (64-символьное имя вылезало за край), удаляется одним
движением, и без него ломается не косметика, а раскладка страницы. Мутация
**O7** — красная.

**`inset:-.4rem` у `.back::before`** — покрыл, но **как норматив доступности, а
не как строку CSS**. Глиф `<` шириной .8rem = 12.8px — цель для пальца вдвое
меньше минимума WCAG 2.2 §2.5.8 (24×24 CSS-px, уровень AA); псевдоэлемент
доводит её до 25.6px. Тест проверяет не число `-.4rem`, а результат: `width −
2 × inset ≥ 1.5rem`. Мутации: **V3** (правило удалено), **V4** (`inset` сжат до
`-.1rem` — 16px, ниже минимума), **V5** (снят `position:absolute`, без которого
`inset` не делает ничего) — все красные. Доступность — та область, где
экономить на проверке нельзя.

**Что намеренно НЕ покрыл:** `.back{text-align:center}`, `.back{font-size}`,
`content:""`. Ни у одного нет связи с другим числом и внешнего норматива —
тест был бы дословным пересказом строки CSS и падал бы на любой перерисовке,
ничего не защищая.

### Н2. Я уничтожил незакоммиченные правки F24 — важная, процессная

Мой мутационный скрипт откатывал шаблон через `git checkout --
internal/web/templates/layout.html`. В круге 1 это было безопасно: файл совпадал
с HEAD. В круге 2 правки F24 в рабочем дереве **не закоммичены**, и первый же
откат вернул файл к committed-версии, стерев F24 целиком. `git stash` пуст,
`git fsck` пуст — файл ни разу не попадал в индекс, штатного способа восстановить
не было.

Что сделал: немедленно остановился, сообщил командиру, передал всё, что имел
дословно (три правила с комментариями я успел прочитать до поломки), и **не стал
восстанавливать шаблон сам** — это продакшн-файл вне моих границ, а часть текста
(комментарий над `dialog`, размещение `.back::before`) я знал только по отчёту
F24. Частично восстановленный файл, который выглядит целым, хуже явно сломанного:
R9-qa снимал бы метрики с него, а комментарии F24 потерялись бы тихо.

Файл восстановлен командой; проверено маркерами перед возобновлением работы.

Что изменил у себя: откат мутаций теперь **побайтовый** (содержимое читается в
память до правки и возвращается в `finally`), плюс предохранитель — скрипт
отказывается стартовать, если в файле нет маркеров F24. Целостность проверена
sha256 до и после каждого прогона: совпадает.

Системная часть находки, решать не мне: незакоммиченные правки на общем рабочем
дереве несовместимы с агентами, которые мутируют файлы. Либо исполнитель
коммитит до запуска проверяющих, либо проверяющие работают в отдельных worktree.

## Допущения

1. **`h1FontSizeRem = 2.0` взято из умолчания браузера**, а не из CSS проекта —
   `font-size` у `h1` не задан нигде. Тест падает с прямым указанием, если `h1`
   обзаведётся своим `font-size`.
2. **Минимум зоны нажатия — 24 CSS-px** (WCAG 2.2 §2.5.8, уровень AA). Проекту
   уровень соответствия не назначен; взял AA как общепринятый по умолчанию.
   Переиграть — константа `minTargetRem`.
3. **`evalRem` понимает только формы, встречающиеся в проекте** (`Nrem`,
   `calc(100vw - Nrem)`, `min(...)`). Прочее — отказ разобрать, то есть красный
   тест с сообщением про синтаксис. Писать разборщик CSS-длин ради полноты не
   стал.
4. **`gap` из проверок убран намеренно.** Под новым механизмом он к позиции
   заголовка отношения не имеет; оставить его в формуле значило бы требовать
   поломки при его правке (см. O10).
