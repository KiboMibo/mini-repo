### 1. `internal/web/web_t26_test.go:39` — НЕ ослаблен, наоборот строже

Было `strings.Contains(body, "&larr;")`, стало
`strings.Contains(body, "aria-label=\"Back to applications\">&lt;</a>")`.

Новый ассерт **сильнее прежнего**: он привязывает глиф к элементу (aria-label
стоит только на стрелке), тогда как прежний ловил `&larr;` где угодно на
странице. Мутации — все красные:

| Мутация шаблона | Реакция |
|---|---|
| M1 стрелка удалена из обоих шаблонов | КРАСНЫЙ (`web_t26_test.go:37` и `:40`) |
| M2 глиф возвращён на `&larr;` | КРАСНЫЙ (`:40`) |
| M3 `href="/"` → `href="/apps"` | КРАСНЫЙ (`:37`) |
| M4 удалён `aria-label` | КРАСНЫЙ (`:40`) |
| M5 ссылка → `<button onclick="history.back()">` | КРАСНЫЙ (`:37`, `:40`, `:45`) |
| M6 элемент есть, глиф пустой | КРАСНЫЙ (`:40`) |

Дефект формы (находка 3, замечание): ассерт зафиксировал **порядок атрибутов** —
`aria-label` обязан быть последним перед `>`. Мутация M7 (перестановка
`title`/`aria-label`, поведение не меняется вовсе) даёт КРАСНЫЙ с сообщением
«стрелка не нарисована символом &lt;», хотя нарисована. Такой тест наказывает за
безобидную правку разметки и врёт в логе CI о причине.

### 2. `internal/integration/r8_backarrow_test.go:32` — ослаблен (ложно-положителен)

Было `strings.Contains(body, "&larr;")`, стало
`strings.Contains(body, ">&lt;</a>")`.

Чувствительность к прямым поломкам сохранена (M1, M2, M5, M6 — красные; M3
ловится соседним regexp'ом `backLink`). Но ассерт **не привязан к стрелке**: он
ищет «любой якорь, чей текст равен `<`», а такой якорь на странице приложения
может появиться из данных. Доказано пробником на живом сервере:

```
шаблон мутирован: глиф стрелки заменён на &larr;
версия залита с ?filename=%3C (имя "<" проходит naming.ValidateFilename)
строка с &lt;: <td><a href="/download/probe/1.0.0">&lt;</a></td>
на странице есть ">&lt;</a>": true      ← ассерт зелёный
на странице есть class="back" со стрелкой: true (но глиф уже &larr;)
```

То есть при таком содержимом БД ассерт останется зелёным, даже если стрелку из
шаблона убрать совсем. Прежний `&larr;` был отвязан ровно так же, но взяться
`&larr;` на странице больше неоткуда, а `>&lt;</a>` — берётся из пользовательских
данных. **В этом смысле замена ассерта его ослабила**, хотя намерение было
обратным.

Ассерт переписан мной (файл мой): глиф и атрибуты берутся из **одного** якоря,
найденного по `class="back"` + `href="/"`.

### 3. Инвариант «стрелка — обычная ссылка, а не JS» — покрыт, был покрыт и раньше

Оба теста ищут `history.back` / `history.go` в теле страницы, интеграционный —
ещё и `class="back" onclick`. Мутация M5 (замена ссылки на кнопку с
`history.back()`) ловится обоими сразу по трём ассертам. Волна 9 этот инвариант
не трогала и не ослабила. Добавил только явную проверку `onclick` на самом
элементе стрелки — прежняя искала подстроку по всему телу и промахнулась бы мимо
`onclick="location.href='/'"`.

## Находки

### 1. `dialog{min-width:20rem}` обесценивает добавленный в волне 9 `max-width` — важная

`internal/web/templates/layout.html:40`

```css
dialog{…;min-width:20rem;max-width:min(34rem,calc(100vw - 2rem));box-sizing:border-box}
```

По CSS 2.1 §10.4 `min-width` **сильнее** `max-width`. На экране 320 CSS-пикселей
(20rem — iPhone SE, и столько же даёт двукратный зум в окне 640px) `max-width`
даёт 18rem, но `min-width` перебивает это до 20rem: поля у краёв, ради которого
`calc(100vw - 2rem)` и добавлялся, нет вовсе, а на экране уже 20rem модалка
вылезает за край с горизонтальной прокруткой.

Потолок 34rem при этом работает и своё дело делает — сломана только нижняя
половина замысла.

Чинится тем же приёмом, что и `max-width`:

```css
min-width:min(20rem,calc(100vw - 2rem))
```

Гипотеза исправления проверена: с этой правкой тест зеленеет, остальные тесты
пакета не краснеют (мутация N8bis). Проверка при этом не диктует форму —
`evalRem` вычисляет результат выражения, а не сверяет его текст.

Красный тест: `internal/web/web_r9_layout_test.go › TestDialogFitsNarrowViewport`.

Решения, принятые за отсутствующего заказчика:

1. **Ассерты, подстроенные автором правок, я переписал, а не только описал.**

   прежнего контракта — добавлены только привязка к элементу и `aria-label`.
2. **Красный тест оставлен красным.** Помечать `t.Skip` или ослаблять порог не
   стал: находка 1 — настоящий дефект в изменённой волной 9 строке, и её место в
   CI, а не в чьей-то памяти. Общий CI это не блокирует — соседи по волне
   (R9-sec, R9-qa) в свои файлы пишут независимо.
3. **Порог 80% по изменённым строкам не применялся.** Изменённых строк Go в
   волне нет; натягивать процент на HTML нечем и незачем. Вместо него — таблица
   «изменение → чем покрыто» выше, где явно назван один непокрытый пункт и
   причина.
4. **Узким экраном считаю 320 CSS-пикселей (20rem).** Числа в задаче нет;
   320px — общепринятая нижняя граница мобильной вёрстки (iPhone SE) и то же
   самое, что двукратный зум в окне 640px. Переиграть — поменять `narrowRem` в
   `TestDialogFitsNarrowViewport`.
5. **`.back{text-align:center}` намеренно не покрыто.** Свойство ни с чем не
   связано арифметически; тест на него был бы пересказом строки CSS и падал бы
   на любой перерисовке, ничего не защищая.
6. **Тест вёрстки читает `templates/layout.html` с диска**, а не через `embed` —
   так же поступает соседний `web_f22_test.go` (`filepath.Glob("templates/*.html")`).
   Конвенция пакета, не новое решение.
