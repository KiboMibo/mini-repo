# QA-отчёт: R4-qa — приёмка волн 1–4 плана app_artifactory

**Дата:** 2026-08-06
**Область:** весь проект (волны 1–4 плана `docs/plans/2026-08-06-app-artifactory.md`, коммит 2785500)
**Вердикт:** готово с замечаниями

## Резюме

Собранный сервис пройден руками по всем критериям готовности из шапки плана:
сборка/тесты зелёные (включая `-race`), UI-сценарий (логин, CSRF, создание
приложения, multipart-загрузки с хешем/без/с неверным хешем, закрепление
latest) и API-сценарий (Basic Auth, PUT-заливка, latest, download со сверкой
sha256) выполнены curl'ом на живом сервере, `scripts/smoke.sh` проходит,
graceful shutdown не рвёт активное скачивание. Блокирующих находок нет.
Важные — две: гонка одновременных загрузок одной версии даёт 500 вместо 409,
и `err.Error()` внутренних ошибок уходит клиенту в JSON. Документация доведена:
README расширен, созданы `docs/api.md` и `CLAUDE.md`.

## Находки

### Блокирующие

Нет.

### Важные

1. **Гонка одновременных загрузок одной версии → 500 вместо 409 с утечкой пути ФС** — `internal/api/api.go:377-398` (и симметрично `internal/web/web.go:352`)
   Что не так: ранняя проверка дубля (`GetVersion`) и `files.Save` не атомарны. Две конкурентные PUT одной версии обе проходят раннюю проверку; проигравшая падает в `Save` на «file … already exists», эта ошибка не распознаётся (`switch` знает только `ErrHashMismatch` и `MaxBytesError`) и уходит как 500 `internal` с полным путём файла в `message`. Тот же ответ возникнет при рассинхроне БД/диска (строку удалили, файл остался).
   Чем грозит: CI-скрипты, ретраящие по 5xx, будут бесконечно ретраить логический конфликт; в теле ответа раскрывается внутренний путь data-dir.
   Предлагается: в `files` завести сентинел `ErrFileExists` и маппить его на 409 `already_exists` в api/web; в F4.

2. **`err.Error()` внутренних ошибок уходит клиенту** — `internal/api/api.go` (все ветки `writeErr(..., "internal", err.Error())`, например :166, :181, :387) и `internal/web/web.go:380` («upload failed: » + err)
   Что не так: текст ошибок SQL/ФС отдаётся в JSON/HTML аутентифицированному клиенту; в лог при этом ничего не пишется (в api вообще нет логирования ошибок).
   Чем грозит: раскрытие внутренних путей и деталей схемы; диагностика инцидентов только со слов клиента — на сервере следов нет.
   Предлагается: логировать `err` на сервере, клиенту отдавать статичное «internal error»; в F4 или вместе с находками R4-sec.

### Замечания

- `internal/auth/auth.go:155` — сессионная кука без флага `Secure`. За TLS-прокси браузер отдаст её и по http. Прямо сейчас не ломает (README требует TLS-прокси), но стоит флаг конфига вида `-secure-cookies`; вероятно, продублируется в R4-sec.
- `internal/api/api.go:178-193` — `listApps` делает 3 запроса на приложение (`ListVersions` + `LatestVersion`, который внутри снова `ListVersions`); то же в `web.renderIndex`. На ожидаемых объёмах (десятки приложений) не болит, при сотнях станет заметно.
- `internal/auth/auth.go:170-175` — `jsonError` собирает JSON конкатенацией строк. Сегодня аргументы — литералы и это безопасно, но первое же динамическое сообщение с кавычкой сломает JSON. Дешевле сразу `json.Marshal`.
- `internal/config/` — пакета тестов нет (приоритет флага над env проверяется только косвенно через smoke).

## Тесты

**Результат прогона.** `go test ./...` и `go test -race ./...` — зелёные (naming/files/store/auth/web/api; wazero-прогоны небыстрые, суммарно ~2.5 мин под race). Падений нет. Один скип: тест большого файла в `internal/files/files_r2_test.go:69` под `-short` — осознанный, с причиной.

**Качество существующих тестов.** Мутационная проверка (4 точки — hash-сверка, open redirect, semver-сортировка, CSRF) — все мутации пойманы, формальных «всегда зелёных» тестов не обнаружено. Тесты волн 2–3 покрывают краевые случаи из плана: prerelease-semver, override на чужую версию, регистр hex-хеша, traversal, границу max-upload.

**Покрытие стыков.**

| Стык | Happy path | Ошибки границы | Краевые данные |
|---|---|---|---|
| api/web ↔ store ↔ SQLite | есть | есть (404/409/422) | есть (prerelease, дубль, «v»-префикс) |
| api/web ↔ files ↔ диск | есть | есть (hash, too large) | есть (пустой файл, большой файл) |
| auth ↔ store (сессии) | есть | есть (просрочка, неверный пароль) | есть |
| собранный сервис целиком | smoke.sh + ручной прогон | частично | закрывает R4-test (internal/integration, параллельная задача) |
| конкурентная заливка одной версии | нет | нет — находка В1 | — |

**Дописано.** Ничего: дыры покрытия — в зоне владения параллельной задачи R4-test (`internal/integration/`), дописывать туда из QA-worktree нельзя. Рекомендация R4-test/F4: тест на конкурентный PUT одной версии (находка В1).
