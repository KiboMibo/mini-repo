Автоопределение платформы работает на **настоящих** бинарниках: собранные в тесте
`go build` под `linux/amd64`, `linux/arm64`, `darwin/arm64`, `windows/amd64`

(`git archive` merge-base → `go build` → `serve`), затем на нём поднят текущий код —
backfill проставил платформу бинарнику, у архива оставил пусто, данные целы,
повторный старт ничего не портит и не дублирует. Архивы, права, CSRF, стрелка
«назад» — по контракту.

Найдено одно расхождение, и оно блокирующее: **тот же файл с той же неверной меткой

тестом; F20 сверял парность только на архиве без платформы и этого не увидел.

## Находки

### 1. Форма UI молча принимает платформу, противоречащую файлу — блокирующая

- **Где:** `internal/web/web.go:583-605` (в `saveUpload` нет сверки с `platform.Detect`,
  когда пара выбрана руками); контракт-двойник — `internal/api/api.go:732-743`
  (`platform_mismatch`). Решение UI закреплено тестом
  `internal/web/web_t26_test.go:226` («указанное перевешивает определённое»).
- **Чем грозит:** бинарник, собранный под `linux/amd64`, заливается через интерфейс с
  выбранной парой `windows/amd64` и получает в репозитории метку `windows/amd64` —
  ровно та беда, ради которой в API завели 409: расхождение обнаружит тот, кто скачает
  артефакт. Тот же файл с той же меткой через API не проходит вовсе. Это нарушает
  инвариант CLAUDE.md «класс кода ответа на одну и ту же ошибку обязан совпадать в API
  и UI» и повторяет класс находки F11 (та же операция, разные правила в двух
  интерфейсах).
- **Почему это не «просто забыли»:** T25 выбрал отказ, T26 — переопределение, и каждый
  прикрыл своё решение тестом. F20 сверял парность только на «архив без платформы» и
  этот случай не видел. Требуется решение человека, какой контракт правильный, а не
  механическая правка.
- **Предлагается:** свести к одному поведению. Если правильным считается отказ (как
  формулировала задача волны), в `saveUpload` перед созданием версии добавить сверку с
  `Detect` и откат файла — и тогда переписать `web_t26_test.go:226` под новый контракт;
  если правильным считается переопределение — снять `platform_mismatch` из API и
  описать это в `docs/api.md`. Промежуточный вариант «UI переопределяет, API нет»
  оставлять нельзя: он и есть дыра.
- **Тест:** `TestPlatformMismatchParityAPIvsUI` (падает). Утверждение нарочно слабое —
  «оба интерфейса обязаны дать один вердикт», поэтому оно останется верным при любом
  из двух решений.

### 2. Документация волны 8 не написана вовсе — важная

- **Где:** `docs/api.md`, `README.md`, `CLAUDE.md` — 0 упоминаний платформы (проверено
  `grep -ci platform`).
- **Чем грозит:** волна добавила маршрут `PATCH /api/apps/{name}/versions/{version}`,
  параметр `?platform=`, поле `platform` в ответах и три кода ошибок

  заливка архива через UI и через API **сломает существующие пайплайны**, а в README
  об этом ни слова — это ломающее изменение без строчки в документации. Устарел и сам
  инвариант про порядок полей формы: теперь это `csrf_token, version, sha256,
  platform_os, platform_arch, file`.
- **Предлагается:** документационная задача волны (или `F21` тем же куском). T26 это

### 3. `-short` не ловит находку 1 — замечание

- **Где:** `internal/integration/r8_binaries_test.go:129` (`skipIfShort`).
- **Чем грозит:** сценарии с настоящими бинарниками требуют `go build` и по конвенции

  ради скорости, защита исчезнет молча.
- **Предлагается:** ничего не менять в тестах; при заведении CI указать, что `-short`

- **Предлагается:** при следующем касании — прогонять API-половину таблицы и для

## Допущения

Спрашивать было некого (делегированный вызов), поэтому решено самостоятельно:

- **Подопытный бинарник — минимальная программа, а не сам `apprepo`.** Ради проверки
  заголовка тащить 19 МБ на каждую из четырёх платформ незачем; заголовок ELF/Mach-O/PE
  у `go build` одинаков. Сам `apprepo` под хостовую платформу уже проверяет `smoke.sh`.
- **Кросс-сборки кешируются в памяти на прогон пакета** (`crossBuild`). Иначе каждая
  новая `GOARCH` докомпилирует стандартную библиотеку заново, и пакет распухает на
  минуты.
- **Набор платформ — 4 (`linux/amd64`, `linux/arm64`, `darwin/arm64`, `windows/amd64`),
  а не весь словарь.** Здесь проверяется цепочка целиком, а ширину словаря (`386`,
  `arm`, `riscv64`, `ppc64le`, `s390x`, `freebsd`) уже закрывает
  `internal/platform/platform_test.go`.
- **`r8MaxUpload = 32 MiB` вместо общего `defaultMaxUpload = 1 MiB`:** настоящий
  бинарник Go весит ~2 МБ и в общий лимит не влезает.
- **Тест расхождения сформулирован как парность, а не как «UI обязан отвечать 409».**
  Какой из двух контрактов правильный — решение человека; сформулировать тест жёстче
  значило бы предрешить его и заставить `F21` править тесты.
- **Сценарий «сброшенную вручную платформу backfill определяет заново» зафиксирован
  как есть, а не заявлен дефектом.** Backfill берёт все строки с пустой платформой и
  отличить «ещё не смотрели» от «сбросили нарочно» не может; поведение описано в T24 и
  логично для миграции, но заметно: `unknown`, выставленный человеком у распознаваемого
  бинарника, переживёт ровно до следующего рестарта. Тест сторожит, чтобы это не
  поменялось молча; считать это багом или нет — вопрос к владельцу продукта.
- **Проверка «отказ до чтения тела» перенесена с `?filename=` на `?platform=` тем же
  приёмом, что в F19** (запрос с объявленным телом, которое не отправляется), включая
  контрольную половину: без неё тест зеленел бы и на сервере, который отвечает не читая.
- **Сценарий обновления пропускается (`t.Skip`), если нет git-репозитория или ветки
  `develop`** — прогон из архива исходников не должен падать на невозможности поставить
  сценарий.
- **Операция «проставить платформу» добавлена в существующую таблицу
  `r6_parity_test.go`, а не продублирована у себя:** таблица — это и есть механизм
  сверки прав между интерфейсами, второй копии заводить нельзя. Файл в моём владении
  (`internal/integration/**`), параллельная задача R8-sec его не касается (только отчёт).
