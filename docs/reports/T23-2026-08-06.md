# T23 — `?filename=` обязателен при заливке версии

Ветка `feat/T23-filename-required` (волна 7, параллельно с T22 — веб-интерфейс).
Ломающее изменение API.

## Что сделано и зачем

`PUT /api/apps/{name}/versions/{version}` без `?filename=` сохранял версию под
именем `{приложение}-{версия}` — без расширения. Для голого бинарника терпимо,
для архива нет: скачанный файл приезжает без `.tar.gz`, и система его не
опознаёт. Дефолт убран целиком; угадывание по `Content-Type` не заводилось —
выбран строгий вариант, молчаливо неверное имя хуже явного отказа.

Отсутствующий и пустой параметр (`?filename=`) → **400 `filename_required`**.
Код новый и намеренно отличается от `invalid_filename`: «не передал» и «передал
негодное» чинятся по-разному, и в логе CI они не должны сливаться. Поведение при
переданном имени не изменилось: `naming.ValidateFilename` → `400
invalid_filename`.

Текст ответа (дословно, `myapp` / `1.2.3`):

```json
{"error":"filename_required","message":"the ?filename= query parameter is required and must not be empty; it used to default to \"myapp-1.2.3\", and a default without an extension makes an uploaded archive download as a file the system cannot recognise. Name the file exactly as it should be served, extension included, e.g.: curl -u $CRED -X PUT \"$BASE/api/apps/myapp/versions/1.2.3?filename=myapp-1.2.3.tar.gz\" --data-binary @myapp-1.2.3.tar.gz"}
```

Имя приложения и версия подставляются из самого запроса, поэтому пример в логе
CI — готовая к вставке команда, а не шаблон. Требование «диагностируется с
первого взгляда» разложено на три части: что не так (параметр обязателен), как
починить (curl целиком), почему так (прежний дефолт без расширения).

Отказ стоит до чтения тела: версия не создаётся, каталог приложения на диске не
появляется.

## Ключевые решения

- **Отдельный код `filename_required`, а не `validation`/`invalid_filename`.**
  Клиенту (и человеку в логе) нужно различать «параметр стал обязательным —
  добавь один аргумент» и «имя не проходит правила basename».
- **Пустое значение = отсутствующему.** `r.URL.Query().Get` возвращает `""` в
  обоих случаях, и разделять их незачем: лечение одно.
- **Пример строится из запроса.** Дороже на один `Sprintf`, но снимает шаг
  «подставь свои значения» у того, кто чинит упавший пайплайн.
- **Расширение `.tar.gz` в примере** — потому что задача пришла из архивов;
  текст явно говорит «name the file exactly as it should be served», так что
  голый бинарник примером не запрещён.
- **В smoke.sh добавлена проверка отказа, а не только исправлены вызовы.**
  Smoke — это то, что читает CI; регрессия «дефолт вернулся» должна падать там.

## Как проверено

| Сценарий | Чем подтверждён |
|---|---|
| PUT без параметра → 400 `filename_required` | `TestPutVersionRequiresFilename/missing` (api_t23) + блок smoke.sh «upload without ?filename=» (проверяет 400 и `"error":"filename_required"`) |
| `?filename=` пустой → тот же отказ | `TestPutVersionRequiresFilename/empty`; в smoke.sh — отдельный запрос `?filename=` с ожиданием 400 |
| Версия не создана | `TestPutVersionRequiresFilename`: `GET /api/apps/myapp/versions/1.0.0` → `404 not_found` |
| На диске ничего не появилось | там же: `wantPath(dir/myapp/1.0.0, false)` + проверка, что каталога `myapp` в data-dir нет; в smoke.sh — `[ ! -e "$DATA/myapp/4.0.0" ]` |
| Текст ошибки диагностичен | `wantMissingFilename` требует в `message` подстроки `?filename=`, `required`, `-X PUT`, прежний дефолт `myapp-1.0.0`, `.tar.gz`, `cannot recognise`; smoke.sh дополнительно ищет `required and must not be empty` и готовый пример `filename=myapp-4.0.0.tar.gz` |
| Валидное имя → 201 | `TestPutVersionRequiresFilename` (последняя строка) и весь прежний набор тестов пакета через хелпер `putVersion` |
| Негодное имя → прежний `invalid_filename` | `TestPutVersionRequiresFilename` (`?filename=..`) и `TestPutAndGetVersion` |
| Архивное имя `myapp-1.0.0.tar.gz` проходит | `TestPutVersionArchiveFilename`: 201 и `filename` в теле ответа |

## Что осталось за рамками (владельцы — не эта задача)

Прежний дефолт использовали чужие файлы; правку туда не вносил, границы файлов
задачи соблюдены.

1. **`internal/integration/helpers_test.go:118` — `env.putVersion`.** Все ~30
   вызовов `putVersion`/`mustPutVersion` передают `query=""`, поэтому
   `go test ./internal/integration/` падает: **44 теста**, все с
   `filename_required`. Чинится одной строкой в хелпере — подставлять
   `?filename={app}-{version}`, когда `query` пуст (тесты, которым нужен свой
   параметр, передают его как раньше).
2. **`internal/integration/api_test.go:36-41`** — `put_with_correct_hash…`
   ожидает `filename` «по умолчанию» `myapp-1.0.0` (сообщение `want default`);
   после правки хелпера значение сойдётся, но формулировку «default» стоит
   убрать, чтобы не описывать несуществующее поведение.
3. **`internal/integration/r5_helpers_test.go:166-168`** — `defaultFileName`
   с комментарием «mirrors api.putVersion: filename defaults to
   {app}-{version}». Функция останется полезной (это имя, которым заливает
   хелпер), но комментарий врёт о поведении API.
4. **`docs/plans/2026-08-06-app-artifactory.md:185` и `:357`** — контракт
   маршрута и раздел про `api.Register` описывают `?filename=` как
   опциональный с дефолтом `{name}-{version}`. План — источник контрактов,
   правится решением командира.
5. `README.md:258` и все примеры в нём **уже** передают `?filename=` — правки не
   требуют. `internal/web` не затронут: UI-загрузка берёт имя из multipart-части
   и дефолта не имела никогда. Исторические отчёты ревью
   (`docs/plans/reviews/app-artifactory-R4-*.md`) упоминают дефолт как факт на
   момент написания — это архив, не трогал.

## Риски и на что смотреть ревьюеру

- Изменение ломающее по определению: любой клиент без `?filename=` получает 400
  вместо 201. Раскатывать вместе с уведомлением владельцев пайплайнов; строка
  для исправления — в `docs/api.md`, раздел «Совместимость».
- Уже залитые версии не затронуты: имена хранятся в БД (`versions.filename`),
  миграции нет, `/download` отдаёт то же, что и раньше, включая старые
  умолчательные имена.
- Текст ошибки длинный (одна строка ~330 байт). Это осознанно — он адресован
  логу CI, а не UI; в `Content-Length` ответа роли не играет.
- `go test ./...` в этом worktree красный только из-за пункта 1 списка выше;
  `internal/api`, `internal/web`, `internal/store`, `internal/naming`,
  `internal/files`, `cmd` — зелёные.
