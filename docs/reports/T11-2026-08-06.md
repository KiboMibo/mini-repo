# T11 — связка ReadWritePaths и APPREPO_DATA_DIR (docs)

## Инцидент

Debian 13, в `/etc/apprepo/apprepo.env` прописан `APPREPO_DATA_DIR=/data/repo/apps`,
в юните осталось `ReadWritePaths=/opt/apps`. Сервис не стартует:

```
apprepository.service: Failed to set up mount namespacing: /opt/apps: No such file or directory
Failed at step NAMESPACE spawning /usr/local/bin/apprepo: No such file or directory
Main process exited, code=exited, status=226/NAMESPACE
```

Причина: systemd строит mount-неймспейс до запуска процесса и не подставляет
переменные из `EnvironmentFile` в собственные директивы; `ProtectSystem=strict`
делает ФС read-only везде, кроме `ReadWritePaths=`. То есть путь data-dir обязан
совпадать в двух местах, и нигде это не было сказано.

## Что сделано

Только документация, код не тронут.

- `deploy/apprepo.service` — трёхстрочный комментарий над `ReadWritePaths=`:
  путь обязан совпадать с `APPREPO_DATA_DIR`, переменные здесь не раскрываются,
  при смене data-dir править обе строки + `daemon-reload`. Директивы не менялись.
- `README.md`, раздел «Деплой (systemd)» — абзац про эту связку с дословным
  текстом ошибки (`status=226/NAMESPACE`, «Failed at step NAMESPACE»), чтобы
  находилось поиском по симптому; команда проверки
  `systemctl show apprepo -p ReadWritePaths`; одно предложение про альтернативу
  `StateDirectory=apprepo` (+ `APPREPO_DATA_DIR=/var/lib/apprepo`).
  Вставленный в README код-блок юнита (T10) синхронизирован с файлом.
- `CLAUDE.md`, раздел «Инварианты» — одна запись про дублирование пути в двух
  местах и симптом расхождения.

## Решения

- Сам юнит на `StateDirectory=` **не переводим**: у пользователя кастомный путь
  `/data/repo/apps` на отдельном диске, дефолт `/opt/apps` + `ReadWritePaths=`
  остаётся совместимым с этим сценарием. `StateDirectory` упомянут в README как
  вариант для тех, кому свой путь не нужен.

## Проверено

- `awk`-извлечение `ini`-блока из README и `diff -u` с `deploy/apprepo.service` —
  расхождений нет (блок синхронен файлу).
- `systemd-analyze verify deploy/apprepo.service` — синтаксических замечаний нет,
  единственное сообщение: `Command /usr/local/bin/apprepo is not executable:
  No such file or directory` (в песочнице бинарник не установлен, ожидаемо).
- `go build ./...` — OK (санитарная проверка, код не задет).
- `git diff --stat` — только `CLAUDE.md`, `README.md`, `deploy/apprepo.service`.

## Риски

Нет: изменения только текстовые, поведение сервиса и дефолтные пути прежние.
