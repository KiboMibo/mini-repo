# Отчёт F5: молчаливое падение при неверном APPREPO_MAX_UPLOAD

- **Дата:** 2026-08-06
- **Ветка:** `fix/F5-silent-config-error` (от `develop`)
- **Задача:** дефект боевого развёртывания (в плане отсутствует), постановка от командира
- **Файлы во владении:** `cmd/apprepo/main.go`, `internal/config/**`

## Дефект

Сервис под systemd на Debian стартовал и мгновенно падал:

```
apprepository.service: Main process exited, code=exited, status=2/INVALIDARGUMENT
apprepository.service: Failed with result 'exit-code'.
```

В журнале — ни строки от приложения. Причина в `cmd/apprepo/main.go`:

```go
cfg, err := config.Load(args)
if err != nil {
    os.Exit(2) // flag package already printed the error and usage
}
```

Комментарий верен только для ошибок `fs.Parse`: `flag.ContinueOnError` сам
печатает сообщение и usage. Но `config.Load` возвращает ещё и собственную
ошибку `invalid max-upload value %q` из `strconv.ParseInt` — её не печатал
никто, и процесс уходил с кодом 2 в полной тишине. Диагностировать такое на
чужой машине невозможно: нет ни причины, ни имени переменной.

Два из трёх воспроизведений — не выдуманные, а типовые способы прострелить
ногу: systemd в `EnvironmentFile` **не** обрезает хвостовой комментарий после
значения, а env-файл, отредактированный на Windows, приносит `CR`.

## Что сделано

### 1. Ошибка печатается (главное)

`internal/config/config.go` — новый экспортируемый сентинел:

```go
// ErrPrinted wraps errors that the flag package has already reported to stderr
// together with the usage text (unknown flag, bad syntax, -h). Callers must not
// print those a second time; every other Load error is theirs to report.
var ErrPrinted = errors.New("already reported by the flag package")
```

Им оборачивается **только** ошибка `fs.Parse` (`fmt.Errorf("%w: %w", ErrPrinted, err)`);
все прочие ошибки `Load` остаются «чистыми». `cmd/apprepo/main.go` печатает
любую ошибку, кроме помеченной:

```go
func loadConfig(args []string) config.Config {
	cfg, err := config.Load(args)
	if err != nil {
		if !errors.Is(err, config.ErrPrinted) {
			fmt.Fprintf(os.Stderr, "apprepo: %v\n", err)
		}
		os.Exit(2)
	}
	return cfg
}
```

Инверсия («печатаем всё, кроме уже напечатанного») выбрана намеренно: новая
собственная ошибка в `config` по умолчанию окажется видимой, а не молчаливой.
Обратный вариант — типизированная `config.Error` только для своих ошибок —
даёт ту же картину сегодня, но повторяет исходный дефект при любом будущем
`return Config{}, fmt.Errorf(...)`, который забудут обернуть.

Текст ошибки называет и значение, и обе ручки:
`invalid max-upload value "2G" (APPREPO_MAX_UPLOAD or -max-upload): expected a positive number of bytes`.

Заодно на тот же `loadConfig` переведён `userAdd` — он молчал ровно так же.

### 2. Терпимость к мусору вокруг значения

`envOr` теперь обрезает значение через `strings.TrimSpace` (покрывает и `\r`,
и `\t`, и пробелы) — для **всех** `APPREPO_*`, а не только для `max-upload`:
путь `/srv/apps ` с хвостовым пробелом ломает старт не менее эффектно, просто
падает не в разборе числа, а в mkdir.

Значение с хвостовым комментарием (`2147483648 # 2 GiB`) корректным по-прежнему
**не** считается — systemd передаёт комментарий как часть значения, и молча
угадывать за пользователя, где кончается число, хуже, чем отказать. Отказ
теперь внятный.

### 3. Тесты

`internal/config/config_test.go` — первые тесты пакета (пакет был без тестов
вовсе, замечание 4 в `docs/plans/reviews/app-artifactory-R4-qa.md`):

| Тест | Что проверяет |
|---|---|
| `TestLoadDefaults` | все пять дефолтов, включая `DBPath = /opt/apps/apprepo.db` |
| `TestLoadPrecedenceFlagOverEnvOverDefault` | флаг > env > дефолт в одном прогоне |
| `TestLoadDBPathDefaultsUnderDataDir` | `DBPath` следует за `-data-dir`; явный `-db` не переписывается |
| `TestLoadTrimsEnvValues` | пробелы, `\t`, `\r\n` у addr/data-dir/base-url/max-upload |
| `TestLoadInvalidMaxUpload` | `2G`, `2147483648 # 2 GiB`, `0`, `-1`, `1e9`, `abc` → ошибка, называющая значение и ручку, **не** помеченная `ErrPrinted` |
| `TestLoadFlagErrorIsMarkedPrinted` | ошибка flag-пакета, наоборот, помечена — main не дублирует |

Проверка «не молчим» стоит на уровне `config`, а не `cmd`: содержательное
условие — «ошибка не помечена как уже напечатанная», и это ровно то, на что
смотрит `main`. Тест на самом бинарнике потребовал бы сборки в тесте ради
той же гарантии.

Тесты проверены мутациями (обе поймались, изменения откачены):

- снять `strings.TrimSpace` → падает `TestLoadTrimsEnvValues`;
- обернуть собственную ошибку в `ErrPrinted` → падает `TestLoadInvalidMaxUpload`
  с внятным «error marked ErrPrinted, so main would stay silent».

`clearEnv` гасит все `APPREPO_*` через `t.Setenv("", ...)`, чтобы прогон не
зависел от окружения CI. `quietStderr` подменяет `os.Stderr` на `/dev/null` на
время теста flag-ошибки — иначе usage-простыня лезет в вывод `go test`.

## Изменённые файлы

- `cmd/apprepo/main.go` — общий `loadConfig`: печать ошибки в stderr перед `exit 2`, кроме помеченной `ErrPrinted`; `userAdd` переведён на него.
- `internal/config/config.go` — сентинел `ErrPrinted` на ошибках `fs.Parse`; развёрнутый текст ошибки `max-upload`; `TrimSpace` в `envOr`.
- `internal/config/config_test.go` — новый файл, 6 тестов (первые в пакете).

Ничего вне этих файлов не тронуто. Новых зависимостей нет (`errors`, `strings`
— stdlib). Контракты плана не менялись: `Config` и приоритеты те же.

## За рамками — на отдельную задачу

- **Документация не тронута по указанию постановки.** Стоит отдельным заходом
  упомянуть в `README.md` (раздел конфигурации/деплоя) и/или `CLAUDE.md`, что
  значения `APPREPO_*` обрезаются по краям, а хвостовой комментарий в
  `EnvironmentFile` попадает в значение и валит старт с внятной ошибкой.
  Кандидат и на строку в `deploy/apprepo.env.example`.
- Валидация остальных полей (`Addr` разбирается только `ListenAndServe`,
  `BaseURL` не парсится как URL) осталась как была — расширение поведения, а не
  исправление дефекта.
- Прочие «человеческие» форматы размера (`2G`, `2GiB`) сознательно не
  поддержаны: это фича, а не фикс, и её место — в плане.

## Риски и точки внимания ревьюеру

- **Смена семантики `ErrPrinted`-обёртки.** `config.Load` теперь возвращает для
  ошибок флагов обёрнутую ошибку. Внешних потребителей, кроме `cmd/apprepo`,
  у `Load` нет (проверено поиском по репозиторию), сравнений с `flag.ErrHelp`
  тоже — `errors.Is` сквозь `%w` в любом случае продолжает работать.
- **`TrimSpace` меняет поведение для всех env-переменных.** Значение, состоящее
  только из пробелов, теперь равносильно незаданному (уходит дефолт), а не
  пустому пути. Считаю это правильным, но это именно изменение поведения.
- Флаги командной строки намеренно **не** триммятся: аргумент с пробелом на
  конце пользователь передал явно, а shell не подкладывает мусор так, как это
  делает `EnvironmentFile`.
