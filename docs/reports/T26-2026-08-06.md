# T26 — стрелка «назад» и платформа версии в веб-интерфейсе

Ветка `feat/T26-ui-platform` от `wave/app-artifactory-w8` (в базе — T24).
Только stdlib, новых зависимостей нет, внешних ресурсов в разметке нет.
Параллельно шёл T25 (JSON API) — его файлов (`internal/api`) не касался.

## А. Стрелка «назад»

Слева от заголовка на **странице приложения** (`/apps/{name}`) и на **странице
пользователей** (`/users`) — `←`, ведущая на список приложений `/`.

```html
<a class="back" href="/" title="Back to applications" aria-label="Back to applications">&larr;</a>
```

Обычная ссылка, а не `history.back()`: работает без JS, открывается в новой
вкладке средним кликом и всегда ведёт в раздел выше, а не «туда, откуда
пришли» (после отправки формы история указывает не на список).

Где ещё есть заголовок: `/` — корневой список, возвращаться некуда, стрелки
нет; `/login` — вне сессии; страница отказа (`forbidden.html`) стрелку не
получила намеренно — у неё уже есть текстовая ссылка «Back to applications»
для ролей с `PermUI`, а deployer'у, который на ней и живёт, идти на `/` некуда
(там его встретит та же страница). Шапка с именем вошедшего, ссылкой `/users`
и выходом не менялась.

На `/users` заголовок обёрнут в тот же `div.page-head`, что и на странице
приложения, — стрелка и `h1` выравниваются одинаково на обеих страницах.

## Б. Платформа версии

### 1. Колонка в таблице

`<th>Platform</th>` вторым столбцом. Значение показывается как есть
(`linux/amd64`, `any`) — в колонке лежит только канонический вид, нормализовать
в шаблоне нечего. Пустая платформа — **видимый прочерк** в приглушённой ячейке
с подсказкой `Unknown — set it with the Platform button`, а не пустая клетка:
«неизвестно, можно проставить» должно быть заметно.

### 2. Поле в форме загрузки

Два выпадающих списка **перед** полем `file`:

| Поле | Варианты |
|---|---|
| `platform_os` | `""` — detect automatically · `any` · всё из `platform.KnownOS()` |
| `platform_arch` | `""` · всё из `platform.KnownArch()` |

Списки собираются из словаря (`view.PlatformOS`/`PlatformArch` ←
`platform.KnownOS()`/`KnownArch()`), а не перечислением в разметке: копия
разъехалась бы с тем, что принимает `platform.Parse`. Тест сверяет их в обе
стороны — каждое значение словаря есть в форме, и в форме нет ничего, кроме
словаря, `""` и `any`.

Поле `file` осталось **последним** — записанный инвариант (хендлер читает части
потоково, `FormData` обходит поля в порядке разметки). Стережёт прежний
`TestUploadFormFileFieldIsLast`; новые поля вставлены выше него.

Подсказка под списками: оставьте `detect automatically` для голого бинарника —
ОС и архитектура читаются из файла; у архива читать нечего, поэтому выберите
пару руками (или `any`, если файл от платформы не зависит), иначе заливка будет
отклонена.

### 3. Ручная простановка у существующей версии

Кнопка `Platform` в строке версии открывает модалку с теми же двумя списками,
в которых **подставлено текущее значение** (`linux/arm64` → `linux` + `arm64`;
`any` → `any`; пусто → `unknown`).

```
POST /apps/{name}/versions/{version}/platform   →  form(auth.PermVersion, …)
```

Маршрут повешен через существующий `form` = `guard` + CSRF, то есть
`RequireSession` → `Require(PermUI)` → `Require(PermVersion)` → проверка токена.
Второй копии матрицы прав не появилось; кнопка в разметке — под тем же
`{{if $.Can.Version}}`, что и удаление версии. Первый пункт списка ОС —
`unknown`: он же **сброс** платформы в «неизвестно» (`SetVersionPlatform(id, "")`
мимо `Parse`, для которого пустая строка — ошибка). Негодная пара — 400 с
текстом `platform.Parse` (он перечисляет допустимые значения) и модалкой строки,
отрендеренной открытой.

### 4. Заливка через UI

Порядок в `saveUpload`:

1. `platformField` разбирает пару **до чтения тела** — негодная не должна стоить
   клиенту гигабайта трафика (тот же порядок, что у имени файла в `putVersion`).
2. Файл принимается и публикуется как раньше.
3. Если платформу не указали — `platform.Detect` по **уже опубликованному** пути
   (путь временного файла пакет `files` наружу не отдаёт). Ошибка чтения — то же
   «неизвестно», но с записью в лог.
4. Платформы всё ещё нет (архив, скрипт, чужая архитектура) — **400 с понятным
   текстом на странице**, модалка загрузки открыта, файл убран с диска, версия
   не создана.

```
could not tell from the file which OS and architecture it is built for
(archives carry nothing to read): pick them in the upload form, or "any" if
this file does not depend on a platform. Nothing was stored.
```

Это **изменение поведения**: заливка через интерфейс теперь требует, чтобы
платформа в итоге была известна — либо определилась, либо была указана. Так
сформулировано решение пользователя («указывать вручную обязательно только
когда автоопределение не сработало»); угадывать `any` за пользователя нельзя —
это выдало бы чужой бинарь за переносимый (T24). Последствия для чужих тестов —
ниже, в разделе «Точки внимания».

## Ключевые решения

**Два списка вместо одного с парами.** Декартово произведение словаря — это 28
пунктов, половина из которых бессмысленна (`darwin/s390x`). Два списка короче,
а склейка и проверка пары всё равно одна — `platform.Parse` в `platformField`.
Цена: выбрать ОС и не выбрать архитектуру технически можно — это 400 с текстом
словаря, а не молчаливая запись половины.

**`any` — вариант списка ОС, а не отдельный флажок.** Он взаимоисключающ с
любой ОС, и радиокнопкой это выражается ровно так же, но дороже; выбранная при
`any` архитектура игнорируется (в комментарии к коду это сказано).

**Определение — после публикации, отказ — с откатом файла.** `files.Prepare`
не отдаёт путь временного файла, а лезть в его внутренности ради определения
неправильно: пакет намеренно закрыт. Поэтому файл сначала публикуется, а при
отказе убирается `rollbackFile` (тот же путь, что и при неудачной вставке
строки). Неудача уборки — только в лог, но громко: оставшийся файл вернёт 409
на повторной попытке, и оператор должен это увидеть.

**Ошибка `SetVersionPlatform` после успешной заливки — 500, но версия
остаётся.** Откатывать удачную публикацию из-за одной колонки неправильно;
платформа при этом пустая и проставляется руками на той же странице.

**Ввод не переносится обратно в форму при отказе.** С JS (обычный случай в
браузере) страница не перезагружается вовсе — XHR показывает баннер, а
заполненная форма остаётся как была. Без JS перерисованная модалка открыта, но
поля пустые — как и у прежних отказов («version already exists»). Отдельного
эха значений не делал: это касается всех форм проекта сразу и тянет на общее
решение, а не на правку одной.

## Точки внимания для ревьюера

- **`internal/integration` красный — 10 тестов, и это следствие моей правки, а
  не параллельной задачи.** Все они льют через UI-форму текст или архив без
  платформы и ждут 303, а теперь получают 400. Файлы не мои (в задаче
  перечислены только `internal/web/**`), поэтому не чинил. Проверено
  экспериментально и откачено: одна строка в общем помощнике
  `internal/integration/helpers_test.go` (`uploadUI`, добавить
  `"platform_os": "any"` в карту полей) чинит 5 из 10. Остальные пять собирают
  тело вручную: `TestUIEdges`, `TestUIUploadAtExactLimitIsAccepted`,
  `TestUIUploadLimitIsCountedOnBytesRead` (`edges_test.go`),
  `TestBackslashFilenameStoredAsBasename` (`misc_test.go`),
  `TestUploadSurvivesClientLeavingAfterFullBody`
  (`f18_upload_after_body_test.go`) — в каждом добавить ту же часть формы перед
  файлом. Прошу отдельную задачу `F` (как F17 после ломающего `?filename=`).
- **Расхождение UI и API до слияния с T25.** Интерфейс требует платформу, API
  (пока) нет. Это не нарушение инварианта о классах кодов (одна и та же ошибка
  — 4xx в обоих), но поведение стоит сверить с T25 при слиянии: если API
  оставит заливку без платформы разрешённой, разница должна быть осознанной и
  описанной в `docs/api.md` и README.
- **`scripts/smoke.sh` заливает только через API**, поэтому текущего сценария
  «архив без платформы через UI» не покрывает; smoke зелёный.
- **`CLAUDE.md` и `README.md` не обновлены** — они за документационной задачей
  волны. Что стоит туда занести: порядок полей формы теперь
  `csrf_token, version, sha256, platform_os, platform_arch, file` (инвариант про
  «file последним» упоминает три поля), и требование платформы при заливке
  через UI.
- **Список ОС в интерфейсе всегда полный**: пара вроде `windows/riscv64`
  выбирается, хотя такого не бывает. Словарь `platform` их тоже принимает —
  сужать надо было бы в нём, не в разметке.
