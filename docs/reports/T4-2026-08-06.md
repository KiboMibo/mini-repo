## Ключевые решения

1. **`store.GetUserByID` — новый файл в чужом пакете.** Дыра в контракте: сессия хранит только `user_id`, а store умеет `GetUser(username)` — после `RequireSession` пользователя нечем достать для `CurrentUser`. Спросить некого, поэтому минимальный аддитивный хелпер отдельным файлом `internal/store/user_by_id.go`: существующие файлы store не тронуты, контрактные сигнатуры не изменены, текстовый конфликт с T5/T6 исключён (они store не редактируют). Альтернатива — класть в контекст `User{ID}` без username — сломала бы UI T5 втихую.
2. **Тело 401 в `RequireBasic` — JSON** `{"error":"unauthorized","message":"…"}`: критерий T6 требует JSON-401 на `/api/…`, а 401 отдаёт именно middleware; для `/download` контракт JSON допускает («допустим text» — тем более JSON). T6 ничего доделывать не нужно.
3. **Тайминг:** при неизвестном пользователе bcrypt прогоняется по фиктивному хешу (`dummyHash`), ветки «нет пользователя» и «неверный пароль» стоят одинаково и возвращают один `ErrInvalidCredentials`.
4. **`safeNext`:** в `next` уходит только `r.URL.RequestURI()`, отфильтрованный до относительного пути (`/…`, но не `//…` и не `/\…`). Находка по ходу: `RequestURI()` для absolute-form target (`GET https://evil/x`) сам отбрасывает scheme/host — фильтр остаётся защитой в глубину.
5. Ошибки store в middleware не глушатся — 500, а не тихий редирект на логин.

## Критерии приёмки → подтверждение

| Критерий | Чем подтверждён |
|---|---|
| Basic с верными кредами пропускает + user в контексте; неверные → 401 + `WWW-Authenticate` | `TestRequireBasic` (valid/wrong password/unknown user/no header) |
| Session без куки → 303 `/login?next=…`; с валидной — пропускает | `TestRequireSession` (+ expired, garbage cookie) |
| `LoginUser` с неверным паролем → ошибка, куки нет; кука HttpOnly, SameSite=Lax, Path=/, 7 суток | `TestLoginUser` |
| open-redirect через `next=https://evil` невозможен | `TestNoOpenRedirect` (httptest absolute-form + юнит `safeNext`) |

## За рамками / для ревьюера

- `LogoutUser` игнорирует ошибку `DeleteSession` (сигнатура без error; кука гасится всегда, просроченная строка подчистится в `GetSession`) — помечено комментарием.
- `jsonError` собирает JSON конкатенацией литералов — экранирование не нужно, входов пользователя там нет.
- Смотреть в первую очередь: решение №1 (файл в `internal/store/`) — единственное отступление от границ владения.
