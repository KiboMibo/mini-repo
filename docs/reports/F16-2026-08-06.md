# F16 — честное предупреждение о старых именах и правдивый «not found» в CLI

- **Ветка:** `fix/F16-legacy-accuracy` (от `wave/app-artifactory-w6`, remote нет — не пушилось)
- **Коммиты:** `0bf8600`, `fff06c0`, `601054b`
- **Закрывает:** важную находку 2 и первое замечание из
  `docs/plans/reviews/app-artifactory-R6-qa-round2.md`
- **Дата:** 2026-08-06

## Что сделано и зачем

**1. Предупреждение обещало больше, чем есть.** Текст CLI (`legacyNameWarning`) и
абзац на `/users` говорили про все учётки со старыми именами «they still work and
can sign in». Приёмка проверила живьём: `"admin "` и `"аlice"` входят и по Basic,
и в UI, а `"ci:bot"` по Basic получает 401 — заголовок кодирует `user:password`,
и всё до первого двоеточия читается как имя. Для роли `deployer` (в UI не пускает
роль, по Basic — протокол) такая учётка мертва полностью, а сигнала об этом
оператор не получал.

Теперь оба текста разделяют два случая, по одной дополнительной фразе на каждый:
рабочие старые имена (пробелы, не-ASCII) — неудобство в адресации по имени;
имя с двоеточием — по Basic не входит вовсе и разбирается первым. Совет по
починке (удалить и завести заново, обновить Basic-креды) остался один и общий.
Фраза про двоеточие печатается и рендерится **только когда такие учётки есть**:
рабочему старому имени приписывать отказ Basic так же неверно, как обратное.

На `/users` пометки теперь разные: `legacy name "admin "` (оранжевый значок, как
раньше) против `broken name "ci:bot"` (красный, как у блокировки) — оператору
видно, что одна учётка сломана, а другая просто неудобна.

**2. CLI печатал не то имя, которое искал.** `mustUser` искал нормализованное имя,
а в «not found» выводил исходный аргумент: `apprepo user role "admin " developer`
отвечал `user "admin " not found`, хотя в `user list` строка `"admin "` видна.
Ложное «строки нет» ровно в сценарии разбора старых имён. Печатается
нормализованное имя.

## Новые тексты дословно

**CLI (`user list` → stderr, журнал при старте `serve`)** — собирается из трёх
кусков; ниже фактический вывод на базе с `"admin "`, `"аlice"`, `"ci:bot"`:

```
warning: 2 account(s) have legacy names ("admin ", "аlice"): they still work and
can sign in, but are not addressable by name from the API or CLI. 1 account(s)
have a colon in the name ("ci:bot"): HTTP Basic encodes user:password, so these
cannot sign in over Basic at all — with the deployer role, which has no web UI
either, such an account is dead; fix these first. There is no way to rename an
account, so the only fix is to delete such an account on the /users page of the
web UI (where accounts are addressed by numeric id) and create it again under a
valid name; the new account gets new Basic credentials, so update them wherever
they are used (CI)
```

Без имён с двоеточием печатается то же без второй фразы; без старых имён вовсе —
ничего (`legacyNameWarning` возвращает `""`).

**Абзац на `/users`** (фраза про двоеточие — под `{{if .Broken}}`):

> Some accounts have a **legacy name** — a name from before name validation
> (spaces, a colon, non-ASCII letters); the exact name is shown in quotes next to
> it, because a trailing space is invisible otherwise. A name with spaces or
> non-ASCII letters still works and can sign in, but it is not addressable by name
> from the API or CLI. A name with a colon is worse and marked **broken name**:
> HTTP Basic encodes `user:password`, so everything before the first colon is read
> as the user name and such an account cannot sign in over Basic at all — with the
> `deployer` role, which has no web UI either, it is dead; fix these first. There
> is no way to rename an account: delete it here and create it again under a valid
> name — the new account gets new Basic credentials, so update them wherever they
> are used (CI).

**Значки в строке таблицы:**

- `legacy name "admin "`, фон `#b45309`, title `Not addressable by name from the API or CLI`;
- `broken name "ci:bot"`, фон `#b91c1c`, title `Cannot sign in over HTTP Basic at all: it encodes user:password`.

**CLI, ненайденный пользователь:** `apprepo: user "admin" not found` (было
`user "admin " not found`), exit 1.

## Что осталось за рамками

- Поведение не менялось нигде: правки — тексты, разбиение отбора и одна строка в
  `mustUser`. Учётка с двоеточием как не входила по Basic, так и не входит;
  автоматического переименования по-прежнему нет намеренно.
- Третье замечание круга 2 (сырая дата в `users.html:30`) не трогалось — оно вне
  задачи.
- `mustUser` печатает только нормализованное имя, без исходного: исходное видно в
  самой команде оператора, а второе имя в строке отказа опять уводило бы внимание.
