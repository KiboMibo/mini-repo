# F27 — релизные сборки и представительное описание

**Статус: DONE.** Проект готов к первому публичному релизу: `make dist` собирает
пять платформ с зашитой версией, README открывается шапкой и быстрым стартом.
Открытым остаётся выбор лицензии — решение владельца, см. раздел «Лицензия».

## Что сделано и зачем

**1. Версия в бинарнике.** Раньше её не было вовсе: у скачанного файла нельзя
было спросить, что это за сборка. Добавлены две переменные в `main`
(`version = "dev"`, `commit = "none"`) и разбор `version` / `-version` /
`--version` **первой строкой `main`** — до подкоманд и до `config.Load`, чей
`FlagSet` неизвестный флаг отверг бы. Существующий разбор (`serve`, группа
`user`, `cutFlag`/`cutBoolFlag`) не тронут: проверка стоит выше него и смотрит
только на `args[0]`, а `args[0] == "version"` до этого был ошибкой «unknown
command». Умолчания оставлены рабочими — `make build` без `-ldflags` собирается
и печатает `apprepo dev (commit none)`.

**2. Кросс-платформенные сборки.** `make dist` → `scripts/dist.sh`. Пять целей
собраны фактически, не предположительно: `file` подтверждает
ELF x86-64 / ELF aarch64 / Mach-O x86_64 / Mach-O arm64 / PE32+.
`CGO_ENABLED=0` проставлен явно — драйвер SQLite чистый Go (wazero), так что
кросс-компиляция обходится без тулчейнов.

**3. Шапка README.** Файл на 58 КБ был подробным руководством без входной точки:
первый экран — сплошной абзац описания. Добавлены заголовок-строка сути, бейджи,
короткое «Что это», «Быстрый старт» и оглавление. Прежний вводный абзац
**сохранён дословно** и переехал под заголовок «Что умеет» — он остаётся
подробным описанием возможностей, просто перестал быть первым, что видит
человек. Ниже текст не тронут.

## Цели Makefile

| Цель | Что делает |
|---|---|
| `build` | `go build -o apprepo ./cmd/apprepo` — как было, без изменений |
| `test` | `go test ./...` — как было |
| `run` | `go run ./cmd/apprepo` — как было |
| `dist` | `bash scripts/dist.sh` — пять платформ, архивы и `SHA256SUMS` в `dist/` |
| `clean` | `rm -rf dist apprepo` |

`make dist VERSION=v1.0.0` задаёт версию явно; без неё берётся
`git describe --tags --always --dirty`, коммит — `git rev-parse --short HEAD`.
Оба падают в `dev` / `none`, если git недоступен (сборка из распакованного
tarball).

Что делает `scripts/dist.sh`: для каждой из пяти пар GOOS/GOARCH собирает
`-trimpath -ldflags "-s -w -X main.version=… -X main.commit=…"`, кладёт рядом
`README.md` (и `LICENSE`, если он появится) с правами 0644 — в репозитории файлы
лежат с 0600, и в архив для чужой машины это ехать не должно, — пакует в
`.tar.gz` (linux, darwin) или `.zip` (windows), в конце считает `SHA256SUMS`
(`sha256sum`, а где его нет — `shasum -a 256`). `dist/` очищается перед сборкой,
чтобы вчерашние артефакты не попали в сегодняшний `SHA256SUMS`.

## Лицензия — решение за владельцем

Лицензии в репозитории нет. Для публичного репозитория это не мелочь: без неё
код формально «все права защищены» — сторонний человек не вправе им
пользоваться, даже скачав. Файл не создавал намеренно: выбор лицензии —
решение владельца, а не исполнителя. Три разумных варианта:

- **MIT** — три абзаца, разрешает всё, включая закрытые производные, требует
  только сохранять текст лицензии. Максимум использования, минимум обязательств
  у пользователя. Умолчание для утилиты, которую хочется видеть везде.
- **Apache 2.0** — та же свобода, плюс явная выдача патентных прав и
  прекращение их при патентном иске, плюс требование помечать изменения. Длиннее
  и формальнее; предпочтительна, если проект будут тащить в корпоративный контур,
  где юристы смотрят на патентную оговорку.
- **AGPL-3.0** — обязывает открывать исходники производных, в том числе если
  ими крутят сетевой сервис. Защищает от закрытого SaaS поверх этого кода, но
  ощутимо сужает круг корпоративных пользователей.

Рекомендация: **MIT**, если цель — чтобы инструментом пользовались; **Apache
2.0**, если важна патентная определённость. `scripts/dist.sh` уже кладёт
`LICENSE` в архивы, как только файл появится в корне — менять ничего не
придётся.

## Точки внимания для ревьюера

- **`zip` — единственная внешняя зависимость сборки.** Скрипт проверяет наличие
  и отказывается с внятным текстом. На macOS и в типовых CI-образах он есть; в
  голом `golang:alpine` его нет. Если это станет мешать, `.zip` можно собирать
  и стандартной библиотекой Go, но заводить для этого отдельную программу
  сейчас — лишний код.
- **Версия в имени архива берётся из `git describe`.** Пока тегов нет, имена
  выходят вида `apprepo_21a7954-dirty_linux_amd64.tar.gz`, и `-dirty` честно
  говорит, что дерево грязное. Для настоящего релиза нужен тег (или
  `make dist VERSION=v1.0.0`).
- **Бейдж Release** ссылается на `KiboMibo/mini-repo` и до первого релиза
  покажет «no releases» — это нормально и починится само выпуском.
- **Оглавление собрано по существующим заголовкам вручную**, автогенерации нет.
  Новый раздел `##` в README придётся добавить в список руками; тестом это не
  стережётся (в отличие от блока `ini`).
- **Быстрый старт ведёт на страницу релизов, а не на прямую ссылку** вида
  `releases/latest/download/<файл>`: в имени архива есть версия, поэтому
  «последний» прямой ссылкой не адресуется без её знания.
