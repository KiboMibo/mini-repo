# T24 — платформа версии: словарь, автоопределение, хранение, backfill

Ветка `feat/T24-platform` от `wave/app-artifactory-w8`. Фундамент волны 8: на
сигнатуры ниже закладываются T25 (API) и T26 (UI). Только stdlib, новых
зависимостей нет.

## Что сделано и зачем

У версии появилась **платформа** — ОС и архитектура, для которых собран
бинарник. Хранится пара, а не одна архитектура: `amd64` сама по себе
двусмысленна, бинарь под Linux и под Windows не взаимозаменяемы.

Два пути заполнения, потому что распространяются и голые бинарники, и
многофайловые архивы:

- **автоопределение** по заголовку файла (`debug/elf`, `debug/macho`,
  `debug/pe`) — работает на голом бинарнике;
- **ручное указание** — обязательно только там, где автоопределение не
  сработало. Заливка платформу не требует, поэтому старые CI-скрипты,
  льющие бинарники, продолжают работать без единой правки.

Версии, залитые раньше, определяются при старте проходом по файлам на диске;
что не опозналось — остаётся пустым до ручной простановки.

## Реализованный контракт (дословно)

```go
// internal/platform
const Any = "any"

func Parse(s string) (string, error)         // "linux/amd64", "any"; регистр к нижнему
func Detect(path string) (string, error)     // "" без ошибки, если формат не опознан
func KnownOS() []string                      // для выпадающих списков UI
func KnownArch() []string

// internal/store
type Version struct {
	ID        int64
	AppID     int64
	Version   string
	Filename  string
	SizeBytes int64
	SHA256    string
	Platform  string // "os/arch", "any" или "" — платформа неизвестна
	CreatedAt time.Time
}

func (s *Store) SetVersionPlatform(id int64, p string) error // "" допустимо (сброс)
```

Именованные результаты в контракте задачи (`canonical string, err error`) на
вызывающих не влияют; в коде они не названы там, где не нужны для `recover`.

### Что должны знать T25 и T26

- `""` — «неизвестно», нормальное состояние: старые версии и архивы. Не ошибка.
- `Parse("")` — **ошибка**, а не «неизвестно». Сброс платформы — это
  `SetVersionPlatform(id, "")` напрямую, мимо `Parse`.
- `Parse` приводит регистр к нижнему и обрезает края строки; всё остальное
  строго. `"amd64"`, `"linux/"`, `"linux/amd64/x"`, `"plan9/amd64"`,
  `"linux\x00/amd64"`, пустая строка — ошибка. Текст ошибки перечисляет
  допустимые значения и рассчитан на показ пользователю как есть:
  ```
  invalid platform "amd64": expected "any", or os/arch where os is one of
  linux, darwin, windows, freebsd and arch is one of amd64, arm64, 386, arm,
  riscv64, ppc64le, s390x
  ```
- `SetVersionPlatform` сам прогоняет непустое значение через `Parse` и кладёт
  канонический вид (`"Linux/AMD64"` → `linux/amd64`), как `CreateVersion`
  канонизирует semver. Это дублирование валидации намеренное: в колонке лежат
  только значения из словаря, и UI может показывать их без нормализации.
  Обновление, не нашедшее строки, — ошибка (`version %d not found`), как у
  `SetLatestOverride`.
- Словарь для списков — `KnownOS()`/`KnownArch()`; обе функции возвращают
  копию, испортить пакетный словарь из UI нельзя. Полный набор пар — их
  декартово произведение плюс `any`.

## Как устроены миграция и backfill

**Миграция.** Симметрично `migrateUsers`: `store.Open` вызывает
`migrateVersions`, тот через `addColumns` читает `pragma_table_info('versions')`
и делает `ALTER TABLE` только для отсутствующих колонок. Идемпотентно: на
готовой таблице выполняется один `SELECT`. Существующие строки получают `''` из
`DEFAULT`.

Умолчание задано **дважды** — в `schema.sql` (для новых БД, `CREATE TABLE IF NOT
EXISTS` существующую таблицу не трогает) и в `migrateVersions` (для старых). Это
записанный инвариант проекта, в обоих местах стоит комментарий-напоминание.

Общая часть цикла вынесена в `addColumns(db, table, cols)`, `migrateUsers`
переведён на неё. Мотив: третья миграция стала бы третьей копией одного и того
же цикла, а расхождение копий здесь — это молча непроведённая миграция. Имя
`migrateUsers` сохранено — на него ссылается CLAUDE.md, и смысл инварианта не
изменился.

**Backfill.** `internal/app/backfill.go`, вызывается из `New` на каждом старте.
Слоёвость: `store` не знает ни про `files`, ни про data-dir, а в `app` известны
оба — там же лежат `cfg` и открытый store. Проход: `ListApps` → `ListVersions` →
строки с `Platform == ""` → `platform.Detect(fst.Path(app, version, filename))` →
`SetVersionPlatform`. Свойства:

- **старт не падает никогда**: отсутствующий, битый или враждебный файл —
  пропуск со счётчиком, а не ошибка запуска;
- **одна строка в лог**, а не строка на версию:
  `app: platform backfill: checked 5 version(s), set 2, skipped 3`
  (при сбое в конце добавляется `(first error: …)` — первая ошибка, чтобы
  проблема не растворилась в счётчике);
- **на пустой БД молчит** и ничего не делает (`checked == 0` → выход без лога);
- **повторный старт безопасен**: берутся только пустые строки, `Detect` на одном
  и том же файле отвечает одинаково. Неопознаваемые версии (архивы)
  переспрашиваются каждый старт — это дешёвое чтение заголовка и цена того, что
  архив, перезалитый бинарником, определится сам.

Запрос версий делается по приложению (`ListVersions` на каждое), а не одним
join'ом: отдельный запрос ради старта не оправдан, счёт приложений в такой
установке идёт на десятки. Проход синхронный — платформа обязана быть на месте
до первого запроса, а не «когда-нибудь».

## Автоопределение: что во что отображается

Словарь один на пакет (`knownOS`, `knownArch`), из него берут значения `Parse`,
карты `debug/*` и списки для UI. Каждое значение из карт перед возвратом
проходит `Parse` (функция `canonical`), а тест сверяет содержимое карт со
списками — «отобразилось во что-то, чего UI не знает» невозможно.

ELF-ключ — это машина **плюс класс плюс порядок байт**: `EM_X86_64` в 32-битном
классе это x32 ABI, а не amd64; `EM_PPC64` в big-endian это не `ppc64le`. Обе
пары словарю неизвестны и дают `""`. ОС для ELF: `linux`, кроме
`ELFOSABI_FREEBSD` (Go помечает freebsd именно так — проверено на собранном
бинарнике). Mach-O — всегда `darwin`, PE — всегда `windows`.

Неизвестная машина — **не ошибка, а `""`**: репозиторий не должен отказывать в
работе из-за архитектуры, о которой не слышал.

## Недоверенный ввод — чем закрыт

`debug/elf` и соседи разбирают ровно тот файл, который залил пользователь. Три
рубежа в `Detect`:

1. **`recover` на границе.** Паника внутри `debug/*` превращается в ошибку
   `detect platform: panic while parsing <path>: …`; сервис не падает. Рубеж
   стоит выше вызова всех трёх разборщиков, забыть его на новом формате нельзя.
2. **Файл не читается целиком.** В разборщик уходит `*os.File` как
   `io.ReaderAt` — берутся только заголовки. Тест меряет `TotalAlloc` на файле
   в 64 MiB с валидным ELF-заголовком впереди и требует меньше 8 MiB.

   > **Неверно, исправлено в F21.** Рубеж не работал: при заголовке, который
   > честно указывает внутрь большого файла (`e_shnum == 0` с расширенной
   > нумерацией секций, либо `shstrtab` во весь файл), `debug/elf` читает файл
   > целиком — 256 MiB превращались в 2,4 GB аллокаций и 10 с (R8-sec S1).
   > Тест промахивался потому, что за валидным заголовком в нём лежал мусор,
   > на который заголовок не ссылался. Теперь в разборщик уходит обёртка со
   > счётчиком прочитанных байт (`detectBudget`, 1 MiB).

3. **Только регулярный файл.** `fstat` после открытия; каталог, FIFO, симлинк
   на устройство — `("", nil)`, без разбора. Без этого чтение заголовка с
   `/dev/zero` не закончилось бы никогда.

   > **Про FIFO неверно, исправлено в F21.** Проверка стояла ПОСЛЕ `os.Open`, а
   > открытие FIFO без `O_NONBLOCK` блокируется в ядре до появления писателя —
   > до `fstat` дело не доходило, и `app.New` на такой data-dir не возвращался
   > никогда (R8-sec S3). Каталог и симлинк на `/dev/zero` отсекались верно.
   > Теперь открытие идёт с `O_RDONLY|O_NONBLOCK`, есть тесты с `Mkfifo` в
   > `internal/platform` и `internal/app`.

Тесты на враждебный ввод (`TestDetectHostileInput`, `TestDetectSymlink`,
`TestDetectDoesNotReadWholeFile`): пустой файл, один байт, только магия ELF,
4 KiB нулей, 64 KiB мусора с фиксированным зерном, `MZ` без остального,
обрезанный ELF-заголовок **на каждой длине от 1 до 63**, валидный заголовок с
инвертированным байтом **в каждой из 64 позиций**, заголовок с гигантской
таблицей секций (`shnum=0xffff`, `phnum=0xffff`, `phoff` за пределами файла),
симлинк на бинарник (определяется), симлинк на `/dev/zero` (`""`), симлинк в
никуда (ошибка чтения), каталог. Критерий у всех один: не паникует, а результат
либо `""`, либо ошибка, либо строка, проходящая `Parse`.

Отдельно тот же сценарий проверен на уровне старта
(`TestBackfillIgnoresHostileFile`): враждебный файл в data-dir не мешает
приложению подняться.

## Что осталось за рамками и почему

- **API и UI платформы** — T25 и T26, их файлы не трогал.
- **Проверка совпадения платформы с содержимым при ручном указании** не
  делается: пользователь вправе пометить `any` архив, который внутри содержит
  ELF. Автоопределение — подсказка, а не арбитр.
- **Fat/universal Mach-O** (несколько архитектур в одном файле) даёт `""`:
  `macho.NewFile` такой файл не берёт, а одной строкой пару архитектур не
  выразить. Если понадобится — это отдельное решение о формате значения, а не
  правка `Detect`.
- **Определение при заливке** (проставлять платформу автоматически для новых
  версий) в задаче не заявлено и в `api`/`web` не добавлялось — это T25.
  `platform.Detect` для этого готов и вызывается одной строкой.
- Отката миграции нет, как и у T18: колонка только добавляется. Требование
  «снять копию БД перед обновлением» в README уже есть.

## Риски и точки внимания для ревьюера

- **`Parse` обрезает края строки.** Осознанно (урок F18: `?filename=$VAR` с
  незаданной переменной), но это отступление от буквального «строгая». Если
  T25/T26 ожидают отказ на `" linux/amd64 "` — скажите, правка в одну строку.
- **`SetVersionPlatform` валидирует сам.** Если T25 захочет писать в колонку
  что-то мимо словаря, он получит ошибку. Это намеренно.
- **`addColumns` затрагивает существующую миграцию `users`.** Поведение то же,
  покрыто прежним `TestMigratePreT18DB` (проходит без правок), но это рефакторинг
  кода, который выполняется на каждом старте — стоит взгляда.
- **Backfill синхронный в `New`.** На установке с очень большим числом
  неопознанных версий это добавляет к старту по одному открытию файла на версию.
  Для текущего масштаба незаметно; если станет заметно — лечится флагом или
  разовой командой, но не в этой задаче.
- **`ELFOSABI_NONE` → `linux`.** ELF используют и другие ОС; бинарник для
  Solaris или NetBSD будет назван `linux/*`. Осознанное упрощение: в словаре
  этих ОС нет, а Go для них помечает OSABI только у freebsd.
