## Что сделано

Сервис собран в работающее целое: полный wiring вынесен в новый пакет
`internal/app`, `serve` получил таймауты и graceful shutdown, реализована
подкоманда `user add`, добавлены systemd unit, env-пример, сквозной
smoke-скрипт и README.

## Ключевое решение: конструктор для интеграционных тестов (для R4-test)

```go
// internal/app
func New(cfg config.Config) (http.Handler, *store.Store, error)
```

`New` создаёт `cfg.DataDir` и каталог БД (`MkdirAll`), открывает store,
собирает `files.Storage`, `auth.Auth` и mux с `web.Register` + `api.Register` +
`GET /healthz`. Возвращает handler и store; закрытие store — на вызывающем.
R4-test поднимает полное приложение так: `h, st, _ := app.New(cfg);
defer st.Close(); srv := httptest.NewServer(h)`.

## Изменённые файлы

- `internal/app/app.go` — новый пакет, конструктор полного приложения.
- `cmd/apprepo/main.go` — serve через `app.New`; `http.Server` (ReadHeader 10s,
  Idle 120s, WriteTimeout нет — осознанно, чтобы не рубить длинные скачивания);
  shutdown по SIGTERM/SIGINT без дедлайна (ждёт активные ответы); `user add`
  (пароль из `APPREPO_PASSWORD` или интерактивно дважды через `x/term`;
  не-терминальный stdin без env — ошибка); подсказка в лог при пустой таблице
  users.
- `go.mod`, `go.sum` — `golang.org/x/term v0.34.0` + replace на зеркало
  `github.com/golang/term v0.34.0` (по образцу существующих; версия выбрана в
  пару к запиненному `golang/sys v0.34.0`).
- `deploy/apprepo.service` — unit по плану (`DynamicUser=no`, `User=apprepo`,
  `EnvironmentFile=/etc/apprepo/apprepo.env`, `Restart=on-failure`,
  `ReadWritePaths=/opt/apps`) + базовый hardening (`ProtectSystem=strict`,
  `NoNewPrivileges`, `PrivateTmp`).
- `deploy/apprepo.env.example` — все пять переменных с комментариями.
- `scripts/smoke.sh` — сборка → `user add` → serve на свободном порту и
  временном каталоге → 401 без Basic → create app → PUT 1.0.0 (с хешем) и
  1.2.0 (без) → PUT с неверным хешем = 422 и файла на диске нет → latest =
  1.2.0 → скачивание latest со сверкой sha256 и заголовков → pin 1.0.0 →
  unpin auto → SIGTERM. `set -euo pipefail`, `trap cleanup EXIT`, `/opt/apps`
  не используется.
- `README.md` — сборка/запуск, таблица конфига, curl-примеры всех основных
  маршрутов, деплой через systemd, предупреждение про Basic Auth без TLS
  (требование reverse-proxy — фикс риска из плана). Углубит R4-qa.

## Критерии приёмки

| Критерий | Подтверждение |
|---|---|
| `make build` собирает бинарник | `go build` зелёный; smoke собирает бинарник тем же путём |
| `scripts/smoke.sh` проходит целиком | прогнан: `SMOKE OK`, все шаги зелёные |
| `user add alice` с `APPREPO_PASSWORD` без интерактива | шаг `user add` в smoke (`APPREPO_PASSWORD=s3cret … user add alice`) |
| SIGTERM завершает без обрыва (graceful) | `Shutdown(context.Background())` без дедлайна ждёт активные ответы; SIGTERM-шаг smoke: сервер логирует `shutting down` и выходит сам |
| Unit-файл валиден | `systemd-analyze verify` в песочнице прогнан: единственная жалоба — отсутствие `/usr/local/bin/apprepo` на машине разработки (ожидаемо), синтаксис принят. Запуска под systemd в песочнице нет |

## Как проверено

```
go mod tidy && go build ./... && go vet ./... && go test ./...   # всё зелёное
bash scripts/smoke.sh                                            # SMOKE OK
```

Плюс отдельный прогон `serve` на пустой БД — подсказка
`no users exist yet; create one with: apprepo user add <username>` в логе есть.

## За рамками / честные оговорки

- Интерактивная ветка `user add` (терминальный ввод пароля дважды) проверена
  только чтением кода — в песочнице нет tty; env-ветка покрыта smoke.
- Graceful «без обрыва активных ответов» не проверялся под длинным скачиванием
  (нечем в bash без гонок); гарантия — семантика `http.Server.Shutdown` без
  дедлайна. При желании R4-test может закрыть это httptest-сценарием.
- Запуск под systemd не проверялся (нет systemd в песочнице) — только
  `systemd-analyze verify` + ручная сверка директив с планом.

## Точки внимания для ревьюера

- `app.New` возвращает store вторым значением — закрытие на вызывающем;
  зафиксировано в docstring.
- Shutdown без таймаута: зависший клиент может держать процесс до
  `TimeoutStopSec` systemd (по умолчанию 90s), который затем пришлёт SIGKILL —
  сознательный компромисс в пользу целостности скачиваний.
