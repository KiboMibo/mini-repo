# T6 — JSON API + скачивание

- **Дата:** 2026-08-06
- **Ветка:** `feat/T6-api`
- **Задача:** T6 из `docs/plans/2026-08-06-app-artifactory.md`
- **Статус:** DONE (интеграционные аспекты — в T7/R4)

## Что сделано

Пакет `internal/api`: `api.Register(mux, st, fs, a, cfg)` по контракту — все 8 JSON-маршрутов `/api/…` и `GET /download/{name}/{version}` (включая `latest`), всё под `a.RequireBasic`. Единый формат объекта версии с `download_url` от `cfg.BaseURL` и вычисляемым `is_latest`; все ошибки API — JSON `{"error","message"}` по кодам контракта.

## Файлы

- `internal/api/api.go` — роуты, хендлеры, JSON-хелперы, download (~430 строк).
- `internal/api/api_test.go` — httptest-юниты на все критерии приёмки.

## Ключевые решения

1. **401 в JSON без правки чужого пакета.** Тело 401 пишет middleware `auth.RequireBasic` (владение T4, формат его тела мне неизвестен). Для `/api/` цепочка обёрнута в `json401` — перехватчик `ResponseWriter`, который при `WriteHeader(401)` подменяет тело на контрактный JSON `unauthorized`, сохраняя `WWW-Authenticate`. Для `/download/` текстовый 401 оставлен как есть (план это явно допускает). Альтернатива — просить T4 писать JSON — ломала бы UI-использование того же middleware.
2. **Вложенный `ServeMux` для `/api/` + catch-all.** Позволяет повесить Basic Auth одним `mux.Handle("/api/", …)` и отдавать JSON-404 на неизвестные пути/методы внутри `/api/` вместо текстовых 404/405 stdlib. Побочный эффект: неверный метод на существующем пути даёт 404, а не 405 — в кодах контракта 405 нет, счёл допустимым.
3. **Ранняя проверка дубля в PUT** (`GetVersion` до чтения тела): не гонять гигабайты, чтобы потом получить 409 от UNIQUE. Гонка всё равно закрыта: UNIQUE в БД → `ErrExists` → 409 + `files.Remove` (откат файла).
4. **Скачивание через `os.Open` + `http.ServeContent`:** `Content-Length`, `Content-Type` по расширению и Range-запросы бесплатно; `Content-Disposition` через `mime.FormatMediaType` (RFC 2231/5987 для не-ASCII имён — совместимо с требованием плана). `latest` отдаёт файл напрямую, не редирект.
5. **Лимиты тела на всех входах:** `MaxBytesReader(cfg.MaxUploadBytes)` на PUT (превышение → 413 `too_large`), 1 MiB на JSON-тела POST.
6. **`POST /api/apps/{name}/latest` отвечает** результирующим объектом latest-версии (или `null`) — формат ответа в плане не задан, зафиксировал так.

## Заглушка internal/auth (не закоммичена)

T4 пишется параллельно, в этом worktree пакета нет. Для локального прогона создавалась минимальная заглушка `internal/auth` строго по контрактным сигнатурам (Basic-разбор + `GetUser` + сравнение через `CheckPassword`); перед коммитом удалена, в коммиты не входит. Тесты `api_test.go` используют только контрактный API (`auth.HashPassword` → `CreateUser` → `SetBasicAuth`), поэтому обязаны работать и с реальным bcrypt-auth от T4.

Следствие: в этой ветке `go build ./...` не компилируется без `internal/auth` — это ожидаемо до слияния с T4 в волне 4 (T7).

## Как проверено

- Со заглушкой: `go build ./... && go vet ./... && go test ./...` — всё зелёное (api: 8 тестов, ok).
- Критерии приёмки T6:
  - 401 без Basic на `/api/…` (JSON `unauthorized`) и `/download/…`, с `WWW-Authenticate` — `TestUnauthorized`; поведение с реальным T4-auth — проверяется в T7/R4.
  - `latest` без версий → 404; с override → закреплённая; `auto` снимает — `TestLatestResolution`.
  - PUT: 201 + объект с `download_url`/каноничной версией/дефолтным filename; 422 `hash_mismatch` без следов файла (повторный PUT проходит — значит, файла не осталось); повторный PUT → 409 — `TestPutAndGetVersion`, `TestPutHashMismatch`.
  - `/download/{app}/latest` и `/{version}`: байты идентичны загруженным, `X-Checksum-Sha256`, `Content-Disposition: attachment`, `Content-Length` — `TestDownload`.
  - Дополнительно: 413 `too_large`, invalid_name/version/filename → 400, списки с `versions_count`/`is_latest`/semver desc.

## Риски и точки внимания для ревьюера

- `json401` перехватит и 401, написанный самим хендлером — таких хендлеров в пакете нет, но при добавлении это надо помнить.
- Хеш из `X-Checksum-Sha256` не проверяется на формат (64 hex) — несовпадение любой строки даёт честный 422 от `files.Save`; формат-валидация была бы косметикой.
- `GET /api/apps` делает 2 запроса к БД на приложение (versions + latest) — O(N) запросов на список; по арх-решению 4 («версий немного») сознательно не оптимизировано.
- Проверить после интеграции (T7/R4): реальный `RequireBasic` от T4 в связке с `json401`; поведение на живом сервере с большими файлами (потоковость PUT/download).
