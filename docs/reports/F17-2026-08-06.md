# F17 — концы волны 7 после обязательного `?filename=`

Ветка `fix/F17-filename-fallout` от `wave/app-artifactory-w7`. Правки только в
чужих для T23 файлах: интеграционный набор и план. Поведение API не менялось —
`internal/api/**` и `internal/web/**` не тронуты.

## Что сделано и зачем

T23 убрал дефолт `{приложение}-{версия}` у `PUT /api/apps/{name}/versions/{version}`
(отсутствующий или пустой параметр → 400 `filename_required`). Всё, что заливало
версии без параметра, перестало работать; в репозитории это был интеграционный
набор. Изменение сознательное, откат не рассматривался — правились потребители.

| Пункт из списка T23 | Что сделано |
|---|---|
| 1. `helpers_test.go:118` — `env.putVersion` шлёт пустой query | При пустом `query` подставляется `?filename={app}-{version}` — ровно прежний дефолт, поэтому ни одна существующая проверка не поменяла смысл. Вызовы со своим `?filename=` (7 штук) работают как раньше |
| 2. `api_test.go:36-41` — «want default myapp-1.0.0» | Значение то же, текст ошибки теперь честный: `want myapp-1.0.0 (as sent by the helper)`. Дефолта у API нет, имя приходит из хелпера |
| 3. `r5_helpers_test.go:166-168` — комментарий у `defaultFileName` | Функция оставлена (это по-прежнему имя, которым заливает хелпер), комментарий переписан: «имя, которое шлёт `env.putVersion`, когда тест не передал своё; у API дефолта нет с T23». Оговорка про переименования приложения сохранена — она верна |
| 4. `docs/plans/…:185` и `:357` | Прежняя формулировка зачёркнута, рядом пометка «изменено волной 7 (T23)» с новым поведением — видно и что было, и что стало. Заодно в списке кодов ошибок (`:202`) отмечен добавленный `filename_required` — он в плане отсутствовал |

## Сверх списка T23

T23 искал потребителей по вызовам `putVersion`, поэтому не увидел тесты, которые
собирают PUT-URL сами. Их четыре, все починены тем же способом — явным
`?filename=`:

- **`f10_race_test.go:140`** (`TestUploadDuringRenameAPI`) — самый неприятный
  случай: тест не падал, а **вешал весь пакет**. Отказ `filename_required`
  выдаётся до чтения тела, поэтому приостановленная загрузка не доживала до
  временных байтов, `waitForTempBytes` уходил в `Fatalf`, а `httptest.Close`
  блокировался на живом соединении — `panic: test timed out after 10m`. Именно
  поэтому `go test ./...` на ветке волны не просто краснел, а не доходил до конца.
- **`r6_lifecycle_test.go:66`** — ожидал 201 от developer'а, получал 400.
- **`r6_lifecycle_test.go:98`** и **`r6_parity_test.go:74`** — проверяют вердикт
  по правам (403 против «пропущено дальше»). Формально прошли бы и без правки —
  400 это не 403, — но проверяли бы уже не то: запрос упирался бы в валидацию
  параметра, не доходя до дубля/отказа, ради которых написан. Приведены в порядок
  по образцу T23 в `api_t19_test.go` (в матрице прав PUT шлёт `?filename=`).
- **`r6_migration_test.go:147`** — ожидал 201 при проверке прав мигрированной
  учётки.

Что проверено и правки **не потребовало**: `README.md:258`, `docs/api.md`,
`scripts/smoke.sh` (все уже шлют параметр — это файлы T23), `internal/web`
(UI берёт имя из multipart-части, дефолта не имел), `CLAUDE.md` (про `?filename=`
не говорит), CLI-тесты (`r6_cli_test.go`, `f16_cli_test.go` — версии не заливают),
`docs/plans/reviews/*` (архив, описывает состояние на момент написания).

## Ключевые решения

- **Дефолт восстановлен в хелпере, а не в API.** Одна строка, смысл всех
  существующих тестов сохраняется дословно, а покрытие самого отказа лежит там,
  где ему место, — в `internal/api/api_t23_test.go` и `scripts/smoke.sh` (файлы
  T23). Заводить в интеграции ещё один тест на `filename_required` не стал:
  дубль без новой информации.
- **Имя строится из версии как передана**, а не из канонической: так же сделал
  T23 в `internal/api/api_test.go`. Имя файла — то, что прислал клиент,
  канонизация версии («v1.0.0» → «1.0.0») его не трогает. На единственный вызов
  с префиксом `v` (`cross_test.go:36`, ожидает 409) это не влияет.
- **`defaultFileName` не переименована.** Имя стало чуть менее точным
  («default» теперь про хелпер, а не про API), но переименование задело бы
  `r5_rename_test.go` без выигрыша по сути; расхождение снято комментарием.
- **План не переписан молча.** Зачёркивание + пометка вместо замены: план —
  исторический документ, но и действующий источник контрактов, и агенту важно
  видеть обе версии, чтобы не «починить» API обратно.

## Как проверено

```
go build ./...                  # ok
go vet ./...                    # ok
go test -count=1 ./...          # ok, все пакеты зелёные (integration 97.9s, api 29.6s)
bash scripts/smoke.sh           # SMOKE OK
```

До правок: `go test ./...` не доходил до конца — пакет `internal/integration`
вис на `TestUploadDuringRenameAPI` и падал по 10-минутному таймауту, унося с
собой остальные 44 падения с `filename_required`.

## Риски и на что смотреть ревьюеру

- Хелпер теперь подставляет имя молча. Тест, которому нужно проверить **отказ**
  без параметра, обязан передать `query` явно (`"?filename="` для пустого) —
  иначе хелпер подставит валидное имя. Оговорено в комментарии к `putVersion`.
- `r6_lifecycle_test.go:98` и `r6_parity_test.go:74` проходили бы и без правки:
  это не починка красного, а восстановление смысла проверки. Если ревьюер
  считает такие правки лишними в fix-ветке — они изолированы в одном коммите.
- Пометки в плане намеренно шумные (зачёркивание + жирный текст). Если для
  плана заведут отдельный раздел «изменения контрактов по волнам», это место —
  первый кандидат на переезд.
