- **Задача:** закрыть замечание N2 круга 3 ревью `R6-sec`
  (`docs/plans/reviews/app-artifactory-R6-sec-round3.md`) — обе его части.
- **Коммиты:** `f8d4cae` (текст предупреждения + `naming.LegacyUsername`),
  `3a49c0b` (пометка на странице `/users` и тесты), `99c0122` (README),

## Что было не так

**а) Текст врал.** F14 советовала «rename or delete them in the web UI», но
переименования учётки в продукте нет вообще: у учёток есть создание, смена
роли, блокировка, сброс пароля и удаление, переименование существует только у
приложений. Администратор, следующий подсказке, ищет кнопку, которой нет.

**б) Предупреждение не доходило до места, где проблему видно и чинят.** Оно
печаталось при старте `serve` (установка живёт месяцами без рестарта) и в
`apprepo user list`, а страница `/users` — единственное место, где легаси-учётку
вообще можно убрать, — рисовала `admin ` и `admin` двумя визуально одинаковыми
строками без всякой пометки.

## Что сделано

**Отбор переехал в `internal/naming`.** `naming.LegacyUsername(name) bool` —
тот же критерий, что придумала F14: не «имя невалидно», а «имя не совпадает со
своей нормальной формой». Он ловит и отвергаемое имя (`аlice`, `ci:bot`), и то,
что нормализуется в чужое (`admin ` → `admin`, где операция молча уходит не на
ту строку). Живёт рядом с `NormalizeUsername`, потому что предупреждение CLI и
пометка в UI обязаны отбирать одни и те же учётки; `legacyNames` в
`cmd/apprepo` стала обёрткой в четыре строки поверх него.

**Текст предупреждения** (`legacyNameWarning`, `cmd/apprepo/main.go`) называет
только то, что в продукте есть, и сразу предупреждает о цене починки —
удаление и заведение заново меняют Basic-креды, и это ровно та причина, по
которой F14 отказалась переименовывать автоматически. Дословно:

```
warning: %d account(s) have legacy names (%s): they still work and can sign in,
but are not addressable by name from the API or CLI — there is no way to rename
an account, so the only fix is to delete such an account on the /users page of
the web UI (where accounts are addressed by numeric id) and create it again
under a valid name; the new account gets new Basic credentials, so update them
wherever they are used (CI)
```

(в исходнике — одна строка; `%d` — число учёток, `%s` — их имена через запятую,
каждое через `strconv.Quote`).

**Пометка на `/users`.** `renderUsers` кладёт в шаблон `view.Legacy` —
`map[int64]string`, id учётки → её имя в кавычках, заполняется только для
легаси-имён. Шаблон берёт значение через `{{with index $.Legacy $u.ID}}` и
рисует у строки значок `legacy name "admin "`. Кавычки (`strconv.Quote`, тот же
приём, что в CLI) здесь несущие: без них хвостовой пробел не виден и пометка
теряет смысл. Над таблицей — короткое пояснение с тем же рецептом; оно
показывается только при непустой карте, поэтому в здоровой установке страница
выглядит как раньше.

**README.** Абзац про старые имена повторял то же несуществующее переименование
и цитировал старый текст предупреждения — переписан: реальный путь, оговорка
про новые Basic-креды и CI, новый текст дословно, упоминание пометки на
`/users`. В `docs/api.md` обещания переименования учётки нет (проверено
`grep` по «rename»/«переименован» — там только переименование приложения), файл
не тронут.

## Ключевые решения

- **Предикат, а не список, в `naming`.** Ревью предлагало вынести туда саму
  `legacyNames`, но она принимает `[]*store.User`, а `naming` — низший слой и
  про `store` не знает (и знать не должен: он же валидирует имена до касания
  БД). Вынесен критерий; оба вызывающих делают свой цикл в четыре строки под
  свой тип результата — список в кавычках для CLI, карта по id для шаблона.
  Разъехаться нечему: сравнение с нормальной формой существует в одном месте.
- **Карта `id → закавыченное имя`, а не флаг в строке таблицы.** Не пришлось
  ни менять тип `view.Users`, ни заводить `userRow` рядом с `appRow`, ни
  добавлять функции в шаблон: `{{with index $.Legacy $u.ID}}` даёт и признак,
  и текст. Пустая карта ложна в шаблоне, поэтому пояснение над таблицей
  включается тем же условием без отдельного поля.
- **Значок несёт само имя, а не только `title`.** Ревью допускало `title` с
  закавыченным именем, но подсказка, которую видно лишь при наведении, не
  помогает беглому просмотру — ровно тому сценарию, ради которого пометка и
  делается. В `title` осталось объяснение последствия («не адресуется по имени
  из API и CLI»).

## Что осталось за рамками

- **Переименование учётки как операция.** Ревью называло его вторым вариантом
  починки N2-а. Не делалось намеренно: это новая операция в трёх интерфейсах,
  с вопросом о судьбе Basic-кредов и сессий, — задача уровня плана, а не
  правки замечания. Текст теперь описывает то, что есть.
- **Пометка в API (`GET /api/users`).** Ответ учётки фиксирован контрактом
  (`username`, `role`, `disabled`, `created_at`), добавлять туда поле ради
  подсказки — менять контракт; CLI и так печатает предупреждение.

## Риски и на что смотреть ревьюеру

- Единственное семантическое изменение поведения — текст: отбор учёток тот же,
  что был в F14 (переезд предиката без правки условия), проверено старым
  `TestLegacyNames` и новым `TestLegacyUsername`.
- Значок на `/users` виден любому, кто дошёл до страницы, то есть только
  `PermUserAdmin` (маршрут под `guard`, не менялся). Имена учёток такой
  пользователь и так видит в таблице — новой утечки нет.
- Имя в значке проходит через `html/template`, поэтому кавычки в выводе —
  `&#34;`; тесты сверяются именно с экранированной формой.
