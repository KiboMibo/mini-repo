Some accounts have a legacy name — a name from before name validation (spaces, a colon, non-ASCII letters); the exact name is shown in quotes next to it, because a trailing space is invisible otherwise. A name with spaces or non-ASCII letters still works and can sign in, but it is not addressable by name from the API or CLI. {{if .Broken}}A name with a colon is worse and marked broken name: HTTP Basic encodes user:password, so everything before the first colon is read as the user name and such an account cannot sign in over Basic at all — with the deployer role, which has no web UI either, it is dead; fix these first.{{end}} There is no way to rename an account: delete it here and create it again under a valid name — the new account gets new Basic credentials, so update them wherever they are used (CI).
